# 正常回库终点的微小航向偏差

2026-10-04用户截图：实机点击路径DONE、110/110缓存、进度2086mm，实际场地X=104.5cm、Y=103.1cm，车头显示-0.0°；点击回启停区后报“目标：车体/安全裕量超出场地边界”。

DONE为正常完成，按用户此前明确的规则，回库继续规划避障；只有手动STOP和保护停车后的下一次回库跳过规划限制。普通回库不倒放旧路径，仍从最新位姿按当前地图规划。

根因已离线复现。目标选项“保持当前”把实际微小偏角也作为启停区终点航向。280×260mm车体、额外10mm安全裕量，启停区中心(2250,2250)mm到外墙只有150mm：标准0°车头长边半长140mm加10mm裕量正好贴边；实际-0.005°（界面保留一位小数显示-0.0°）在终点使包络额外伸出约0.012mm，从而INVALID_GOAL。实际-0.02°时伸出约0.049mm。碰撞判断没有出错，回库使用的终点航向不合适。

修复仅应用于回启停区按钮：目标固定为用户场地车头0°，独立于普通点击目标的航向选项；选项内容不改。core.plan_home_path保留实际起始航向，在当前位置检查完整车体和实际航向到最近标准方向的旋转扫掠，确认安全后才在标准方向网格上规划返回。航向对齐作为明确的TURN台账保存，实机整批会执行实际转头连接；不伪造起始定位或直接取整车体，也不减小裕量、移动启停区中心或绕过障碍。若起点对齐不安全或目标确实不安全，明确拒绝。

传输量化还发现相关问题：小于0.01°的转角可能量化为同一姿态，合并重复点时曾把新ROTATE附加到首点，而固件首点只允许STOP。合并量化后的同姿态不再附加新的ROTATE；保留已有STOP和有效转头标志。实际非零编码转角仍上传独立ROTATE点。

本次仅修改PC规划与点表生成，不修改STM32固件、不烧录、不连接或驱动车辆。已有程序需重启加载更新。
