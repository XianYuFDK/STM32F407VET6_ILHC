# 实机关键坐标整批接入（2026-10-05）

地图点击路径、正常回库和“实机自动跑图”使用与PC坐标模拟相同的七参数闭环。先回读STM32当前RAM的KPX/KPY/KPZ/XVMAX/ZVMAX/XVMIN/ZVMIN，按这组参数完成实际响应预演和量化后的矩形/相邻扫掠检查，再一次上传全部关键坐标。输入框内尚未发送的值不参与规划。

## 使用

1. 更新本次EIDE生成的固件，重启上位机。HEX：`MDK-ARM/build/STM32F407VET6_ILHC/STM32F407VET6_ILHC.hex`。
2. 连接STM32，确认OPS映射和轮使能。整场跑图要求位于所选启停区5mm/3°内；不会自动ZERO。
3. 底盘调参页发送并回读需要的参数。新坐标执行使用该页；“轨迹调参”保留给旧密集轨迹协议。
4. 点击目标或启动实机自动跑图。参数回读、预检、上传期间停车；收到完整点数、CRC及结构检查通过后，仅发送一次TRUN。
5. PASS接近且航向门通过后连续切下点；站点和终点满足位置/航向/实测速度并连续200ms停稳。自动跑图在站点自行续行，最后DONE。不实际扫码/抓取/放置。

正常回库保留真实微小航向偏差：先安全对齐、坐标导航至比赛配置的staging，再保持标准航向入库。前后附加动作同样转换成坐标、随主路径整批上传；没有逐点GOTO。

## STM32接入

- `CCAPS` → `CCAPS 1 2048 3`。新旧能力分开；旧固件只有TCAPS不能误启动新坐标批次。
- `CBEGIN=id,count,map_version,CRC32_HEX,margin,kpx1000,kpy1000,kpz1000,xymax1000,zmax1000,xymin1000,zmin1000`。
- `CPOINT=id,index,x10,y10,yaw100,s10,flags,travel100,pass10,lead10`。
- CRC按小端`<iiIhHhHH`，顺序为x10,y10,s10,yaw100,flags,travel100,pass10,lead10，共22字节；与文本字段次序不同。
- `STOP=1 / WAIT=2`，默认站点只有STOP。TCOMMIT/TRUN/TSTAT/TSTATUS/TABORT沿用。显式WAIT未来可接真实机构完成接口。
- 七参数在CBEGIN核对实际RAM，不符错误20；批次期间拒绝调参，底层参数被改也取消。旧协议与新协议共享64KiB点表缓存，不新增第二份大表。
- 控制周期20ms。误差转车体轴，KPX左右、KPY前后，KPZ角度输出按270mm臂长换算角速度；补偿/逐轴限幅及大于30°时5%平移与PC相同。只传关键点，密集响应数据留PC显示。

## 保护边界

新坐标MCU使用与PC坐标模型相同的相邻骨架75mm偏差门；它不等于旧密集轨迹“margin-2mm”门。MCU没有场地地图，PC负责预检和运行实际矩形及相邻遥测姿态扫掠，运行剩余裕量1mm。旧密集轨迹偏差门未改。不能把75mm门或离线理想回放视为实车碰撞保证。

保留STOP/失能、OPS新鲜度/跳变、会话改变、主机心跳、接收/CRC/序号异常、3秒无进展和180秒总时限。参数读取超时或地图/连接变化不上传；协议能力不符不运行。实际电机响应、定位噪声和实时任务余量仍需上板验证。
