## 已复现的问题

### 1. P1：转向扫掠重复叠加起始航向，可把碰撞转向判为安全

位置：`navigation_planner.py:762-777`，特别是第 775 行。

`scene.footprint.vertices(scene.pad)` 已按 footprint 的 `yaw_deg` 旋转，而 `turn_sweep()` 又按布局绝对航向旋转这些点。起始 footprint 为 90° 时，检查 90°→180° 实际构造的是 180°→270° 的车体扫掠。矩形起止姿态都合法，并不保证中间旋转安全。

反例使用真实车体尺寸 280×260mm、默认 pad=10mm、车心 (1200,1200)、起终点相同、起始 90°、目标 180°。将半径约 0.987mm 的圆障碍置于 (1233.298,1386.203)，算法返回 `model_safe=True`、单次 `TURN_LEFT`、代价 180；独立按绝对角度构造的车体在 122° 时碰到该障碍。该圆是针对几何漏检构造的反例，不能据此断言现有演示地图或 φ50 障碍已经发生碰撞。

修复方向：从 yaw=0 的车体局部顶点旋转到绝对航向，或对已有顶点只旋转相对于 footprint 初始角的增量；加入不同初始角的连续转向碰撞对照。

### 2. P1：非轴向实际航向全部被拒绝，界面正常定位无法规划

位置：`navigation_planner.py:527,550-555`；界面输入在 `main.py:3206-3208`。

`heading_index()` 将实际航向量化到 0/90/180/270°，随后却要求未量化的 footprint 航向与该整数航向误差 ≤1e-6°。界面将真实布局航向同时传给 footprint 和 start_heading，因而即使车只偏了 0.2°，也会返回 `INVALID_INPUT`。

已用真实 MainWindow 方法和 Simulator 复现：OPS yaw=0° 可规划；yaw=0.2° 时同目标 (2250,1600) 报 footprint 航向不一致；yaw=1° 也被拒绝。地图标定旋转不是 90° 整数倍时也会触发。

这是功能阻断，当前拒绝本身是安全的。不能仅删一致性校验或静默把真实车体取整，否则将用错误车体姿态放行。需要明确实现任意初始航向的动作/碰撞模型，或经过扫掠验证的对齐动作及明确界面限制。

### 3. P2：合法 L 形直接返回，绕过更低代价的 A*

位置：`navigation_planner.py:920-936`，特别是第 936 行。

两种 L 形只要第一种可行便立即返回，搜索完全不运行。曼哈顿几何长度最短，不能证明加入前进/后退/横移和转向代价后仍最优。

空场，起点 (500,500)，目标 (500,1500)，起终航向 0°，默认代价：返回横移 1000mm，总代价 1800；合法的“左转90°→前进1000mm→右转90°”代价为 1360。返回值比该可行候选高约 32.4%。

横移上限为 500、转向等效代价 5000 时，550mm 垂直目标还会被快路径直接改为两次转向，返回 10550；未比较按现有连续横移口径允许的分段推进方案。

修复方向：将直接候选作为上界而非立即返回，继续 A* 到能证明最优；只有达到有效代价下界时才可直接结束。

### 4. P2：共线压缩删掉动作切换点，线段失去航向与动作

位置：`navigation_planner.py:623,668-671`，以及 `path_axes()` 的端点配对。

`simplify_collinear()` 只看几何方向，将同一条直线上转向前后的点合并；`path_axes()` 却只按整段起止坐标精确匹配一行 steps。包含多种动作的长几何段不能与任何台账行匹配。

反例：起点 (500,300)，终点 (500,1500)，起始 90°、目标 0°；两侧窄通道和上边界使车必须在 (500,1400) 转向。steps 正确保留“前进1100mm→右转→横移100mm”，points 却合成一条1200mm直线，唯一 LineSegment 的 `heading_deg=None`、`action=''`、`axis_matched=False`；结果仍 `ok=True`。界面没有检查 axis_matched，也没有完整展示 steps 中的原地转向。

原始 steps 尚在，不能说整个回溯已丢失；有问题的是压缩段的语义和界面台账。建议展示几何压缩线与动作分段两份信息，动作分段在航向/动作改变处保留切分点，并显示未匹配状态。

### 5. P2：操作区豁免按任一端点判断，放行整段道路横移

位置：`navigation_planner.py:863-870`，finish 的逐段复查也复用了相同端点口径。

操作区“区内不受横移限制”被实现为“连接边任一端点在区内，整条边不受限制”。连接边可以很长，绝大部分在操作区外。

反例：操作区仅为 [450,550]×[450,550]；起点 (500,500)，目标 (500,1500)，横移上限 0。算法仍成功返回一整段1000mm横移，其中950mm在区外。当前内置 navigation_map 没有 strafe_polygons，加载带操作区的地图后才会触发该配置问题。

修复方向：按与操作区边界的交点切分连接边，明确区外连续横移额度的计算方式；区内豁免应只覆盖区内子段。

### 6. P2：规划快照不能导出 JSON，异常还未被捕获

位置：`main.py:3712-3713`；新增对象位于 `navigation_planner.py:300,321`。

结果里的 segments/corners 是 dataclass 对象。对象虽有 as_dict()，实际导出仍直接 `json.dumps(data)`，没有转换。已调用真实 `_export_navigation_plan()` 复现 `TypeError: Object of type LineSegment is not JSON serializable`；异常处理仅捕获 OSError/ValueError，TypeError 会逃出槽函数。

修复方向：在导出边界明确转换 segments/corners，或统一将结果序列化为基本类型；加入真实导出及读回测试。

## 其他算法限制与验证边界

- 平移碰撞使用整段车体扫掠、合法区域并集、矩形 Minkowski 和圆真实距离；未发现“只检查格点导致越障”的问题。
- `h_state()` 在第1007行使用 forward 系数，而参数校验允许 backward/lateral 小于 forward。此类自定义代价下启发式不再保证可采纳，应该取三种平移系数最小值或约束系数排序。当前 UI 默认系数未触发该问题。
- `attach()` 每个格/航向只保留一个连接候选，优先不消耗横移额度，而非保留代价和剩余额度的非支配候选。这也限制全局最优性，不能在修好快路径后立即宣称整个规划器已全局最优。
- 细网格下连续横移桶反复向上取整，会提前耗尽额度；它是当前实现明示的保守近似，会限制可行性和最优性。网格变细不保证更容易求解。
- body_clearance 的计算跳过 TURN，只代表平移段最小净空，不能解释为包含转向在内的全程最小净空。
- 现有仿真执行明确拒绝含转向路径；实车整条路径执行也未开放。以上转向缺陷首先影响规划安全判定，不能直接推断实车执行过碰撞路线。
- 内置地图 geometry_verified=false，合法区域是整场矩形；实际车道和障碍实测仍是独立前提。
