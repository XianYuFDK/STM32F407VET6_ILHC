# 90°圆弧平滑与完整车体校验（2026-10-02）

规划成功后自动尝试安全圆弧。半径严格依次为 **120、110、100、90、80、70、60mm**，第一个通过的半径即采用；全部失败返回 `ALL_RADII_FAILED`，保留原直角和原地转向，不强行平滑。原 A* 的 `points/steps/segments/corners` 和搜索代价保留；新增平滑轨迹字段供预览和导出。`smooth_arcs=False` 可关闭后处理。

## Corner 与几何

可平滑的 Corner 必须对应台账中单次90°实际转向，两侧行进模式一致（前进、后退或横移），真实航向变化与几何圆弧方向一致；角点须匹配两侧动作段。只换轮模式、掉头、动作模式切换或缺少航向时明确 `NOT_TURNABLE`，不猜测车头方向。

以角点 `P`、入口/出口单位运动方向 `u/v`、半径 `R` 构造：

- 入口切点：`entry = P - R*u`。
- 出口切点：`exit = P + R*v`。
- 圆心：`center = entry + R*v`。
- `cross(u,v)>0` 为布局坐标 `CCW`，扫角 `+90°`；否则为 `CW`，扫角 `-90°`。

两侧直线长度必须足够容纳切点。按路径顺序处理角点，已接受圆弧占用的直线长度从相邻候选中扣除，避免切点交叉或相邻圆弧重叠。允许两个切点恰好相接，剩余长度为0的直线不输出。

航向沿圆弧按真实入口航向加扫角连续变化，入口与出口保持台账原有值。后退、横移、非轴向初始航向都保留其原始语义；无任何航向取整。

## pose_safe 与整段安全性

新增 `CollisionScene.pose_safe(x, y, yaw)`，单位为布局mm和度：

- 使用 `footprint` 指定的真实长宽。界面沿用当前280×260mm矩形；`pad` 在矩形每侧增加安全裕量。
- 使用当前绝对 `yaw` 旋转整个矩形，与车心一起形成完整多边形；缺少真实车体、非有限姿态或退化矩形均拒绝。
- 必须被 `drivable_polygons` 合并白名单完整覆盖，并处于地图 `bounds` 内。支持孔洞和凹形区域，不能只检查车心或四个顶点。
- 不得与固定、模拟、动态矩形相交；不得接触圆形障碍（到圆心的真实多边形距离必须大于实际半径）。圆形障碍没有多边形近似漏检。

整个90°圆弧同时满足 **弧长采样间距≤20mm、角步长≤3°**，包含两个切点。目前这些半径均产生31个姿态。每个姿态调用 `pose_safe`。为覆盖采样间隙，另将相邻车体多边形的凸包按最大顶点旋转半径的弦高外扩，检查完整扫掠包络；外扩补偿Shapely圆弧弦近似。即使小障碍刚好处于两个采样点之间，也不能通过。

最终完整轨迹还复查剩余直线的连续整车扫掠、fallback原地转向，以及所有连接点的位置/航向连续性和原始终点。任何失败均返回 `UNSAFE_TRAJECTORY`，不发布圆弧或平滑点列；时限与取消覆盖后处理阶段。包络检查是保守的，可能拒绝极贴近边界的实际可行圆弧，但不会因采样间隙放行碰撞。

## 返回与界面

| 字段 | 含义 |
| --- | --- |
| `arcs` | `ArcSegment` 对象：角点序号、半径、入口/圆心/出口、CW/CCW、扫角、入口/出口航向、原行进动作、采样姿态、精确弧长；`as_dict()`供JSON |
| `arc_attempts` | 每个可转弯角点按半径顺序的检查结果，包括成功前的失败和候选几何 |
| `arc_fallbacks` | 角点序号、明确原因码、说明；全部半径失败时列出7次失败 |
| `smoothed_primitives` | 完整有序的 `LINE/ARC/TURN` 轨迹；TURN为保留的原地转向 |
| `smoothed_points` | 完整平滑轨迹预览点列，包括全部圆弧采样位置 |
| `smoothed_length` | 剩余直线长度加精确圆弧长度；原地转向长度为0 |
| `smoothing_model_safe` | 完整平滑或fallback轨迹通过当前几何模型检查 |
| `smoothing_status` | COMPLETE全部可转弯角点成功、PARTIAL部分成功、FALLBACK全部候选失败、NO_TURNABLE_CORNER没有可转弯角点；另有DISABLED/NO_FOOTPRINT/INVALID_INPUT/UNSAFE_TRAJECTORY/CANCELLED |

地图显示安全平滑轨迹，圆弧用采样点连线，只在切点和起终点标记航点。台账显示入口、圆心、出口、方向以及fallback原因，JSON导出包含全部上述字段。界面净空下界和原始长度标记为“原台账”，不冒充圆弧轨迹净空。

目前仿真执行器仍只支持固定航向，含圆弧路线明确拒绝执行；`planned_points`保留原台账点列，不把圆弧采样点作为旧GOTO下发。实车自动执行和协议没有改动。

## 障碍快照

`core.plan_path` / `navigation_planner.plan` / `CollisionScene` 接受额外的 `sim_rects/sim_circles/dynamic_rects/dynamic_circles`，与固定障碍合并，搜索、圆弧、fallback复查共用同一份场景。矩形格式为 `[x0,y0,x1,y1,name]`；圆形格式为 `[x,y,radius,name]`。

界面现有模拟障碍直接参与规划场景。地图JSON可包含 `dynamic_rects/dynamic_circles`；界面线程可调用 `MainWindow.set_dynamic_obstacles(rects=..., circles=...)` 更新动态快照，并立即取消旧计划/仿真执行、重画障碍。规划线程使用复制的输入，地图签名包含动态快照，过期计算结果不能恢复旧路径。更新一组时须同时提供另一组需要保留的完整快照。

这里的“动态”指调用者提供的最新障碍位置快照，未新增传感器订阅、障碍速度预测或自动重新规划。
