# 手动/保护停车后直接回启停区

2026-10-04用户最终要求：只有手动触发停止和保护停止后回启停区才不受规划限制。PC模拟与实机采用相同的条件。

| 当前事件 | 下次回启停区 |
| --- | --- |
| 手动STOP、停止比赛、停止实机轨迹、停止模拟跟踪 | 直接返回所选启停区 |
| STM32轨迹FAULT（含错误13）、运行碰撞保护、状态失联保护 | 直接返回所选启停区 |
| 模拟比赛碰撞/控制保护、定位过期、跟踪超时 | 直接返回所选启停区 |
| 正常完成、普通清路径、改地图导致旧计划失效 | 仍规划避障 |
| 发起直接回库后，再次点击回库 | 仍规划，除非又发生新的手动/保护停车 |
| 开始新的手动运动、点击轨迹、比赛或跟踪 | 清除此前停车的例外状态 |
| 新串口会话 | 清除旧会话状态和排队运动 |

直接返回跳过路径规划、可行驶区域/禁区和障碍物门禁，目标使用所选启停区及当前地图到OPS的映射，默认车头为场地+Y的0°。不会重置定位、瞬移、清除障碍或续跑旧比赛。

实机首先取消旧路径并请求STOP。SerialWorker仅在完整成功写入STOP后更新发送时间，短写/超时不更新。GUI等待发送之后的新鲜OPS帧，计算位置/航向变化，平移速度不超过5mm/s、角速度不超过2°/s连续200ms后，发送一次现有GOTO命令。此判据是串口写入成功和实际定位停稳，不是固件STOP应答。未启用轮、定位缺失/过期、标定超出GOTO±300cm范围时拒绝；不会自动启用轮。

回库过程中保留定位和链路检查，目标到位5mm/1°并停稳200ms后显示完成。手动STOP、清路径、重规划、地图/参数变化、失能、定位/链路超时取消回库并清除待发送GOTO；更换会话时不会把旧STOP发给新会话。STOP等待期限5秒，运动期限按直线距离计算且至少30秒。

模拟器调用现有return_home_direct，在状态锁内先处理更早的STOP/失能，再设置本次返回目标；新的STOP/失能可以立即取消。

本次只修改PC端，复用现有STM32 GOTO接口，不改固件、不烧录、不连接实车。需重新启动上位机加载更新。此前错误13的车心保持固件修复仍需使用对应新固件。

验证：`py -3 run_tests.py --qt`完整执行，退出码0。6组核心自检、240项无GUI测试、163项离屏Qt测试全部通过。覆盖正常回库规划、普通清路径/正常完成不放开限制、手动STOP与错误13恢复、模拟实际车体碰撞保护、STOP完整写入/短写、重复遥测不累加停稳、未停稳不发目标、所选启停区和旋转标定、单次GOTO、旧FAULT不重复放开、清路径/手动接管/地图/失能/定位/超时取消，以及新会话清除旧命令。完整日志：`Docs/stop_return_regression_20261004.log`。均为离线验证，未做实车验收。
