# v2.1.10 实机取消原因诊断

用户截图显示 `实机自动跑图 CANCELLED · 31/31点已缓存 · 进度3191mm · 地图、参数或连接变化 · 地图碰撞保护关闭`，当前位置 X=184.9 cm、Y=104.9 cm、航向 0°。

截图能确定上位机取消了批次；该提示来自 BatchUploader 的运行上下文校验失败，随后发送 TABORT 与 STOP。31/31 表示点已上传，不表示车辆已走完31个目标。关闭地图碰撞保护只关闭 PC 的地图车体碰撞检查，不关闭运行上下文、有效定位或连接检查。

旧提示合并了取消信号、串口会话变化、切换模拟、定位缺失/非法、轮失能、连接断开、导航签名变化、任务码/启停区变化，以及有效遥测超过 **350 ms** 未更新。不能仅凭这张截图认定是哪一项；特别是没有手动改地图/参数时，也可能是遥测短暂过期。这不是已证明的实车根因，截图没有取消前的原始帧或检查快照。

本版没有改停车触发条件、350 ms 阈值、扫掠检查或固件控制。只把上下文校验失败分开显示，例如 `OPS遥测过期：400ms未收到有效帧（上限350ms）`、`底盘轮使能已关闭`、`串口连接已断开`、`启停区选择已变化`，或 `导航配置已变化：X偏移、安全裕量`。

BatchUploader 保留原 valid 布尔接口，增加可选 invalid_reason 回调；运行检查与发命令前检查使用同一次失败记录给出的原因，继续发 TABORT/STOP。失败快照保存在实机导出的 `batch.validation_trigger`，包含原因、单调时钟、遥测年龄/阈值、OPS坐标、轮使能、连接状态和变化的字段。非法坐标保存为 null，允许原 JSON 导出。已有直接地图/参数改变的主动取消提示保留。

模拟和固件运动模型沿用 v2.1.9，HEX 无变化。本版只需重启 PC v2.1.10；未连接串口、发送实机命令或重启用户程序。以后发生此类取消，状态栏与“导出实机整批轨迹”可以提供具体触发证据。

验证结果记录在 [取消诊断回归日志](real_cancel_diagnostics_final_20261006.log)。专项验证包括关闭地图碰撞后遥测300ms仍运行、400ms取消且记录原因/快照并发送STOP，未通知的坐标标定改变能指出具体字段，以及上传/运行两个检查位置都保留详细原因和取消命令。

完整上传器与实机 Qt 回归 34 项全部通过，14.377 s，进程退出 0。Python 编译、`git diff --check` 通过。初始测试使用会主动发取消的 NavigationMap 修改而没有走到签名检查，已改用静默标定变化检验签名诊断，未改变主动地图取消行为。
