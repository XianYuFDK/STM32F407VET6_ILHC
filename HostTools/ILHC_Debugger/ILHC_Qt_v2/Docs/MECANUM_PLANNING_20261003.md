# 麦轮比赛规划与模拟初始航向

本节记录上位机PC比赛路径与连续跟踪几何阶段。重启上位机后使用“比赛地图 → 一键比赛模拟”；先手动摆放静态圆柱或随机补齐。当前STM32接入见STM32_BATCH_TRAJECTORY_20261003.md与CLICK_STM32_RETURN_20261004.md。

## 初始车头

普通模拟启动会同时校准启停区位置与OPS到场地的航向映射。
两个启停区默认车头均为0°，朝场地+Y（屏幕上）；90°朝+X（屏幕左）。
“在所选区校准OPS零点”同样使用此基准；实车使用该按钮时，应将车辆按所选区的标定方向摆放。

此前把用户要求的0°按几何角的+X零点处理，错误地将车头转向了X轴。现在界面采用OPS前向零点约定，
两个启停区校准均使用映射旋转0°，比赛初始化实际LAYOUT车头为180°（场地+Y）。
白色三角形也改成尖端朝车头，避免旧图形底边在前、尖端朝车心的歧义。
固件ZERO协议未改变。模拟遥测仍带测量噪声，0°附近可能显示359.x°或0.x°。

## 比赛规划

- 实际车头与运动切线独立；比较前进、倒退、左右横移和转向代价，避免强制保持车头产生长距离横移。
- 车道图仍有横纵车道；麦轮模式增加站点到可见节点的安全斜向边，采用欧氏距离启发式。
- 对候选骨架作整车可见性捷径，直车道优先，浅斜边尝试短接近段连接直车道；整车扫掠允许安全斜行。站点短接头不提前按90°圆弧判死。
- 拐角依次尝试120、110、100、90、80、70、60mm，生成圆心、切点和方向。
  麦轮固定车头支持非90°倒角，使斜线与直线的运动切线连续；全部半径失败则拒绝该候选。
- 当固定车头无路、绕行明显或横向分量≥500mm，比较两个正交车头；固定候选仍有>500mm连续横移时，也比较切线前进/倒退方案。
  比较真实50Hz预演时间、出发转头估计及前进1/倒退1.15/横移1.8的方向代价。下一站沿用真实结束车头，不虚构恢复航向代价。
- 出入库优先固定车头斜线平移；如果扫掠不安全，退回安全L形平移。L形也不安全则明确拒绝比赛。

这是有搜索预算的候选策略，包含贪心捷径、角点半径选择和估计转向代价，不保证连续空间全局最短或整轮全局最优。地图站点仍是名义演示接近点；机械抓放是原来的逻辑模拟，不代表真实机构可以任意角度抓取。

## 连续跟踪、碰撞与导出

`trajectory.py`保持旧切线模式兼容，同时支持显式`heading_mode`：
`TANGENT`、`REVERSE_TANGENT`、`FIXED`。`FIXED`必须提供LAYOUT帧`body_yaw_deg`。

比赛Trajectory为FIELD_MM，全局间距≤20mm，包含以下字段。这里角度仍为计算用几何角：+X为0°、+Y为90°；
界面车头角为`(90 - field_yaw_deg) % 360`。保持几何接口定义，控制器和碰撞使用几何角，界面和目标选择使用+Y零点。

| 字段 | 含义 |
| --- | --- |
| x_mm / y_mm | 场地车心位置 |
| field_yaw_deg | 真实车头角，unwrap |
| tangent_yaw_deg | 行驶切线角，独立unwrap |
| s_mm | 实际几何累计弧长 |
| segment_type | LINE / ARC |
| motion_mode | FORWARD / REVERSE / STRAFE_LEFT / STRAFE_RIGHT / DIAGONAL |

旧隐式切线模式仍输出原五字段。带运动方向的新Trajectory JSON、比赛JSON使用schema_version=2。
比赛路段还保存`driving_points`、`planner`、`body_yaw_deg`（固定模式）、`selection`、`predicted_tracking_s`、`search`和明确fallback。
地图绿色箭头使用运动切线，紫色参考和车辆图标使用实际车头，倒退时两者可以相反。

车体仍为真实280×260mm矩形加用户裕量，完整包含在drivable中，并避开固定设备与模拟圆柱。
固定车头圆弧的连续包络计入**车心绕圆的弦高**；车头旋转时另计车体旋转弦高，不能因角速度零而跳过弧间碰撞。
整段直线连续扫掠，圆弧≤20mm且≤3°采样及采样间包络，全轨迹重新复检。
最后以生产模拟器预演每候选，执行每帧提交前再检查实际矩形扫掠。

固定车头圆弧不需要按车头120°/s限速；仍受250mm/s平移限速及实际碰撞保护。
切线前进/倒退圆弧仍按车头角速度限速。实际单调进度、100mm参考、中间点不停稳、最终STOP连续停稳门、取消与故障保护保留。
