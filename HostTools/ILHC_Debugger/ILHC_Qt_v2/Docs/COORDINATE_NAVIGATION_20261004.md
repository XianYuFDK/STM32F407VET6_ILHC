# PC关键坐标闭环过弯

**2026-10-05更新：参数来源已改为底盘调参，以下独立250/120及schema1为首版历史记录。当前实现见[底盘参数接入说明](COORDINATE_CHASSIS_PARAMS_20261005.md)。**

用户要求采用开源物流车的坐标定位思路：实际X/Y误差按当前航向转到车体轴，再与航向纠偏叠加为四轮速度，平移和转头同时发生，不生成指定半径的圆弧。本次先修改PC模拟；STM32固件、串口协议和实机500mm/s档没有随本轮修改。

## 操作及地图显示

重启上位机，开启“模拟”，加载`competition_map.json`。地图点击规划、功能区目标、正常回启停区及“一键比赛模拟”的TRAVEL使用新坐标控制程序。右侧显示“PC坐标闭环”“无圆弧”，目标列表显示PASS/STOP和目标车头方向。

地图保留Manhattan骨架、实际控制响应的预演轨迹、车头箭头、当前目标坐标及实际行驶轨迹。预演轨迹可以自然弯曲，但没有ArcSegment、圆心、半径或圆弧切线约束。当前参考是关键坐标目标，而非旧轨迹的100mm前视点。

“导出PC路径 JSON”保存关键坐标、通过门和控制参数；“导出Trajectory JSON”在新模式下保存`PC_COORDINATE_REPLAY`诊断预演及原程序，不能作为STM32点表导入。两种导出都重新独立复检当前地图场景。

## 控制过程

新增`coordinate_navigation.py`，`CoordinateTracker`每20ms按实际位置计算目标误差。在内部数学航向θ下：

```text
ex = target_x - actual_x
ey = target_y - actual_y
body_ex = cos(θ)*ex + sin(θ)*ey
body_ey = -sin(θ)*ex + cos(θ)*ey
u = Kpx*body_ex
v = Kpy*body_ey
omega = Kpz*wrap(target_yaw - actual_yaw)

r = radians(omega)*270mm
wheel = (u-v-r, u+v+r, u+v-r, u-v+r)
```

四轮速度在理想麦轮模型中逆解后积分，平移和转头一起执行。这是PC实现的同类控制机制，不是PC调用STM32的`chassis_move`。实际电机延迟、轮胎打滑和OPS误差需要后续实机验证。

PC默认Kpx/Kpy=2.3、Kpz=9、平移上限250mm/s、角速度上限120°/s。参数随程序保存，不使用实机“轨迹调参”页的RAM参数，也不把旧ZVMAX的轮速混合量直接当作deg/s。保持原PC速度便于比较算法，不宣称本轮实现了实机提速。

长直线优先使用沿线车头；根据当前位置到转角目标的距离，开始纠正出口车头。优先选择正向或倒向中转角较小的方向，允许车尾沿运动方向前进。航向误差超过30°时平移限速降至20%，车仍平移，同时纠偏；不会靠高速转头扫进窄道。

规划候选依次尝试`(PASS范围,提前转头距离)`为`(100,200)`、`(100,60)`、`(60,60)`、`(20,40)`mm。实际PASS范围还受两侧短线段各四分之一限制。默认MIN_TURN；需要时比较FORWARD，以及安全固定车头的麦轮侧向方案。侧向方案也受点击规划的允许横移/连续横移上限及作业区限制。

中间PASS达到位置通过范围且出口车头误差小于30°即可切到下一个目标，没有停稳门、不逐20mm样本停车、不跳到自交路线的后续目标。只在最终STOP/比赛站点要求位置、航向和10帧停稳。某些狭窄角点仍可能因位置比例控制而明显减速；不保证每个转角始终保持高速。

同坐标START→STOP用于已到目标后的保持或原地航向对齐，也检查完整旋转扫掠；不允许在多目标路线中塞入重复点。比赛出入库仍保留明确的安全平移/必要航向对齐动作。

## 规划及保护

- A*搜索关键转折坐标，共线合并。图连通检查补充固定车头的麦轮移动能力，避免仅用切线车头误报停靠位不可达。
- 每个候选用相同控制器50Hz完整预演；检查真实280×260mm矩形车体、安全裕量、drivable区域、场地固定结构和当前模拟障碍，以及相邻姿态扫掠。不能只因关键坐标安全而放行。
- 完整比赛共享同一不可变场景的图和精确姿态对扫掠结果缓存；缓存键保留场景对象，不跨地图复用。提交执行及导出再次独立预演，不使用规划缓存。
- 执行每一步仍检查当前实际车体扫掠，保留75mm偏离骨架、3秒无进展、总超时、起点/航向匹配、轮使能和地图版本保护。
- STOP、清路径、重新规划、地图版本变化和会话变化取消旧控制；接受预演期间取消也不能重新挂上旧路径。
- 所有候选失败明确报`关键坐标无安全候选；fallback`，不强行平滑或减少安全裕量。搜索预算耗尽与物理无路分别说明。

关键坐标JSON为`PC_COORDINATE_PROGRAM`/schema1，`waypoints`采用LAYOUT_MM及`layout_yaw_deg`；start/goal参考和诊断轨迹采用FIELD_MM。内部`field_yaw_deg`是数学角，GUI仍以场地+Y为0°，按`90-field_yaw_deg`显示。`hardware_ready=false`。

## 验证与预览

新增控制坐标变换/四轮混合、最短角跨±180°、移动中PASS切换、最终STOP、同坐标保持/对齐与旋转碰撞、途中障碍、横移限制、取消竞争等测试。完整比赛测试令旧圆弧生成函数直接抛错，并删除全部TRAVEL密集预演点表后运行，证明执行只需要关键坐标程序。
