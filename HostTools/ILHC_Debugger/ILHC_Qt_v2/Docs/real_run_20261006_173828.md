左上弯接近目标后的两段持续约2.02秒、2.94秒，期间出现4次、6次明显角速度反向。右上弯也有同类现象，说明不是仅某个地图角点异常。入弯时实测车心速度约80mm/s，符合连续衔接设计；主要问题发生在出口。

例如35.96秒位置距离出口仅1.30mm，但航向87.63°、角速度约24.19°/秒；70.92秒距离仅0.53mm，航向却是88.24°、角速度约-28.76°/秒。位置已进入出口范围时，航向仍不满足1°门，而且还在转动，直接说明两项通过条件错开。

轮心偏离由OPS车心、航向、206×218mm轮心几何和上传圆心推算，不是外部测量的真实轮胎滑移量。TSTAT与遥测异步，区段切换时间有更新延迟；上述时间是日志观测范围，不是精确MCU状态时间。

源码 `Hardware/trajectory_buffer.c` 的 `coordinate_pivot` 中，为不停车而保留80mm/s车心衔接速度；车心圆弧半径149.97mm，对应30.56°/秒。接近终点时，制动曲线仍含这个非零速度项，剩余角度趋近0也不会把旋转请求自然降到0。一旦越过目标，剩余角度改变符号，旋转请求反向，再受180°/秒²加速度限制。这是源码推算的请求，当前日志没有实时请求回读。

与此同时，`coordinate_step` 要求出口位置在2mm内且实际航向误差小于1°才衔接下一段。实车有惯性、执行延迟或滑移时，两个条件可能错开：航向合适时位置还未合适，位置合适时航向已经越过，然后反向纠偏。日志重复出现的约±4.3°振荡与此机制一致，属于高可信控制设计问题；尚不能据此区分电机响应、OPS延迟、地面滑移各自的贡献。

当前理想模型没有实际电机惯性和定位延迟，因而能在窄窗口内一次通过。不能用理想模型通过来证明实机连续转弯稳定，也不宜只降低KPZ：当前非零衔接项在KPZ大于0时仍然存在。

## 回库与优先处理建议

最终OPS为X=0.275mm、Y=0.418mm、航向0.004°，系统成功满足回库判据。OPS自洽不能证明真实库内位置没有累计偏移；之前提到的约4.5cm实车偏差，仍需外部尺量或标记点对照。

1. 优先修改绕轮出口：使用实际相位、位置及可达到的速度约束提前交接下一条直线；失配时进入可收敛的低速纠偏，避免保持非零旋转请求反向追逐出口。增加角速度反馈/响应延迟模型，完整车体扫掠验证要包含过渡段，不能仅放宽2mm/1°门或跳过点位。
2. 普通进站航向切换采用一次锁存或滞回，避免40mm边界反复切换。
3. 停车使用终端低速收敛策略，并结合OPS分辨率和实测噪声重新评估稳定窗口；先保留到站精度约束，不直接把微调超时当作成功。
4. 补充记录控制阶段、实时航向/速度请求、四轮目标与实测反馈，再用相同参数重跑一轮比较。串口新增错误需单独排查，但本轮没有失联取消或重启证据，不能把摇摆直接归因于串口。
