## 修复后的行为

1. 转向从车体局部零角顶点旋转到绝对航向，避免重复叠加初始角。相邻15°采样姿态取凸包，并按含pad的外接半径弦高外扩，覆盖采样间隙；扫掠形状按航向对缓存。量化后的转向车心也重新碰撞检查。
2. 四个航向状态保留真实初始角并相差90°，车体不会取整。前进/后退/横移是最近主轴的动作分类，网格平移仍严格沿布局x/y轴；目标航向须与初始航向相差90°整数倍。界面“保持当前”完全支持非轴向航向。实际车体或裕量越界仍返回INVALID_START/INVALID_GOAL，footprint与真实起始角不一致仍被拒绝。
3. 两种L形及横移/转向连接候选作为代价上界，与网格搜索共同比较；只在候选达到可采纳下界时直接返回。启发式使用三种平移系数最小值，并加必须完成的净转向代价。每个连接状态保留不同额度候选，终点连接序列按到达时剩余额度逐段复核。
4. `points`保留几何共线压缩；`segments`按合并后的MOVE台账分段，在同一直线的航向或动作切换处保留分界。两者的点数可以不同，但长度一致且每个动作段都配上台账。角点按坐标与出现顺序配对，避免重复经过相同位置时配错。界面完整显示steps中的每次原地转向，未匹配动作分段不能显示为成功。含转向路线不再生成固定航向GOTO台账。
5. 操作区豁免按线段与操作区的真实交集计算，支持孔洞并拒绝非法多边形。区外连续横移量跨操作区继续累计，区内距离不消耗额度；只有前进/后退/转向清零。网格和连接段使用同一判据。取消细网格的反复向上分桶，改为精确余量状态；搜索保留取消、时限与400000状态上限。
6. 导出前将segments/corners转换为基本JSON数据，并捕获序列化TypeError；真实导出方法已验证JSON写入和读回。

`max_strafe_run_mm`仍是物理连续横移总长；新增`max_outside_strafe_run_mm`和steps里的`outside_strafe_run_mm`表示区外连续横移量。包含操作区时前者可大于限制，实际按后者判定，界面同时显示两者。

整车净空现在包含转向。旋转包络略大于真实扫掠，故显示为“规划整车外缘净空下界”，而非精确全程最小值。该值对应原规划，执行坐标量化后另行复查安全。

## 已验证结果

- 空场 (500,500)→(500,1500)，起终航向0°：从代价1800的整段横移改为代价1360的两次转向加前进。
- 同路径上限500mm、转向代价5000：搜索会选择代价2015的两段横移加前进/后退打断，比直接两次转向11000更便宜。阶梯推进是已确认的“单次连续”口径后果，保留该行为。
- 原始90°转向漏检障碍：原地转向被拒绝，规划改为移到净空位置转向再返回；独立0.5°密集姿态检查验证各初始航向的扫掠覆盖。
- 主机真实界面方法在场内净空处接受OPS偏角0.2°，并保留实际布局角180.2°。启停区中心默认pad=10mm时，某些偏角会令完整裕量超出场地，这是正确的越界拒绝。
- 原共线动作反例：几何仍为一条直线，动作分段完整保留转向前后的航向和动作，axis_matched=true。
- 区域仅覆盖起点50mm的横移上限0反例：不再放行区外950mm横移；经过200mm操作区的1000mm横移按区外800mm额度正确判定。
- 导出快照可同时读回线段、角点、steps、地图与标定。
