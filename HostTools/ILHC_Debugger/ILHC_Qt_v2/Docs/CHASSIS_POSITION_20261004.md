# 路径执行复用底盘坐标位置闭环（2026-10-04）

修改前已经使用OPS坐标闭环。此次按用户要求，把原`chassis_move`的位置控制核心提取为浮点参考接口`chassis_move_reference`，单点移动与整批路径执行共用该接口，减少两套位置控制公式的重复。

原版本已先在`main`本地提交，提交号`f38e7cb`，包含完整比赛批次、RTOS_APP拆分和500 mm/s调参。本次坐标控制改动不包含在该提交中；没有推送远端。

## 执行方式

1. 上位机A*计算避障路径，平滑、采样、完整矩形车体复检后整批上传。
2. STM32获取一份OPS实际X/Y/Yaw快照，既用于安全检查，也用于本周期位置控制。
3. 依据实际位置更新单调轨迹进度，生成浮点参考X/Y/Yaw及路径速度前馈。
4. `chassis_move_reference`计算目标坐标减实际坐标，使用最短航向误差，输出位置纠偏加前馈。
5. 调用既有世界到车体变换与麦轮速度输出。起步保持、转头保持车心也复用同一个坐标核心。

中间采样点不等待到位；站点与最终STOP保留位置、航向、OPS测得实际停稳200ms检查。没有改成逐点发送GOTO或逐点停稳。车头0°朝场地+Y、倒退/横移、圆弧平滑、量化采样、全部路径一次上传的约定保留。

## 参数

实机路径继续使用“轨迹调参”的TKPX/TKPY/TKPZ和速度规划参数。当前TVMAX=500、TVARC=150、TACC=600、TDEC=1000。公共控制函数只计算坐标误差和控制量，限速、制动、到位判定及安全状态由各调用者负责。

普通`chassis_move/GOTO`继续使用原底盘参数，X/Y增益作用于车体轴，航向控制量为混轮前等效线速度。轨迹增益作用于OPS世界轴，航向控制量为deg/s。共用函数支持两种参数范围，但不直接混用原KPZ与TKPZ数值，不叠加两次位置闭环或轮速斜坡。

公共接口不重新读取OPS，不下发电机，不等待到位，避免本周期保护检查与控制计算使用不同姿态。参考坐标保留浮点精度，179°到-179°按2°最短转角计算；非有限输入或运算溢出清零并拒绝，轨迹进入保护停车，旧单点控制清空目标轮速和到位状态。

## 验证与产物

实际C函数在主机离线编译验证；位置核心测试直接提取固件中的实际函数，与轨迹核心共同链接，不用测试桩替代位置闭环。验证覆盖浮点参考、四向与斜向车头、X/Y独立增益、正负跨±180°、坐标偏差纠正、500 mm/s前馈、倒退/横移、NaN/Inf/溢出拒绝。旧chassis_move坐标变换、限幅、斜坡、到位测试保留。

验证日志：工程根目录`RTOS_APP/validation/chassis-position/native.log`及`eide-build.log`。配套EIDE固件为`MDK-ARM/build/STM32F407VET6_ILHC/STM32F407VET6_ILHC.hex`。

本次未烧录、未连接串口、未驱动车辆。共用坐标核心不代表先前实车圆弧偏差已经消失，原偏差/定位/心跳/STOP保护继续执行。
