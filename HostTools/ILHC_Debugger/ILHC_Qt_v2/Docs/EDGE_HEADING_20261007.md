# 作业区平行停靠（PC 2.1.20）

暂存区原算法把车右侧严格对准设备中心，停车点横向错开50mm时生成79.695°界面航向，导致车身倾斜。用户要求保持实测点，不为对准中心转斜车身。

两默认地图现在显式配置 competition.work_heading_field_deg：原料0°、粗加工180°、暂存90°（界面0°向前、90°向左）。work_heading统一转换到LAYOUT规划航向，快捷作业目标、整轮路线、模拟和实机量化批次共用。沿设备边缘移动停车点不再改变配置的航向；旧自定义地图未配置该字段时保留中心指向算法。

三站坐标仍为原料(10,105)、粗加工(200,105)、暂存(110,190)cm，实际出发OPS置零与回库(0,0,0)不变。尺寸、设备位置、碰撞门槛均未调整。暂存改为正向停靠后，现有模型的车身至设备边缘净空为70mm（之前斜车身约47mm），这不是新增实测结果；保留用户报告的约40mm测量原文，不借助挪地图来强行匹配。

重启上位机2.1.20并重新规划，已有规划不能直接沿用。不需要重新烧录固件。算法和地图散列使旧缓存自动失效，新缓存发布清单与完整回放见 edge_heading_manifest_20261007.json、edge_heading_release_20261007.json；旧缓存保留。

验证包括固定航向不随沿边停车点变化、原三点坐标、模型净空与碰撞、暂存离站位姿残差、Qt快捷目标、OPS原点及配置检查；整场回放覆盖两地图、两种区域选择和默认/实机控制参数。未连接串口、未烧录、未实车验证。
