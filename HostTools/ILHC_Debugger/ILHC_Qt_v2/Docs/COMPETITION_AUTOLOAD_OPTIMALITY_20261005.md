# 实机比赛配置自动加载与路线最优性核算

同日后续已接入新版路线优化器；下文最优性数字是优化前审计。最新选择策略和限定范围证明见[v2.1.4路线优化](ROUTE_OPTIMIZER_20261005.md)。自动加载规则继续有效。

## 自动加载

点击“实机自动跑图：整批上传并运行”时，自动从工程内`competition_map.json`补齐当前地图缺少的`competition`字段：

- 启停区1/2：布局坐标`[2250,2250]`、`[2250,150]`mm。
- 出入库停车区1/2：`[2100,2100]`、`[2100,300]`mm。
- 二维码、原料、粗加工、暂存站点及车道节点。

已有自定义配置保留，部分配置只补缺项，非法显式坐标拒绝运行。完整自定义配置不依赖默认文件。加载只改变内存中的配置快照，并在日志和导出地图快照中记录来源。

当前地图的边界、固定/动态障碍、可行驶区域、版本、核验状态及用户放置的模拟障碍均保留。实机比赛场景补齐动态障碍检查，和当前地图的动态数据一致。没有将默认地图整体替换为名义比赛地图，也没有把`geometry_verified`改成true。

配置在七项底盘参数回读、规划签名和整轮预检之前加载；加载后重复进入回调不会再次替换地图或作废新签名。实际OPS起点仍须在所选区5mm/3°以内，车辆状态、回读、STOP、完整车体及量化后预检继续生效。不会自动ZERO或复位实车位置。

## 最优性结论

**当前算法不保证所有路线都是全局最优，也不保证最短时间。** 它使用有限车道节点、分阶段扩充图、2000次展开预算、前缀候选配额，并优先返回首个安全的非固定车头预演结果。A*名称本身不能为整个带控制器约束的流程提供最优性保证。

本轮按实际代码的骨架代价“距离 + 每次折弯120mm”核算，同时比较控制器预演用时。这是两个不同指标；也不等同于整个比赛的最短用时。

### 独立计算结果

核算覆盖默认导航地图自动补配置、比赛地图；无障碍、两障碍`(1200,1200)/(297,294)`；启停区1/2，共8组完整规划、64个TRAVEL路段。

用独立Dijkstra计算**各路段已选择的有限图**的精确最小代价。状态包含前一节点，以正确计入下一次折弯；不使用生产A*的启发式、前缀配额或展开上限。这一基准放宽了控制器响应/转头等约束，所得值是图上的代价下界。

| 项目 | 结果 |
| --- | --- |
| 达到所在有限图代价下界 | 51 / 64路段 |
| 高于放宽控制约束的图下界 | 13 / 64路段 |
| 最大代价差 | 10.7011% |
| 13条下界骨架经现有27组模式/门限组合预演，满足安全与横移限制 | 0条 |
| 原8个区1无障碍路段，各比较27组现有控制候选 | 1条发现更快安全候选 |

例如两障碍场景“粗加工→暂存”的选择代价6000mm，对应图下界5420mm；后者未通过测试的控制候选，不能把这580mm直接解释为可消除的绕路，更不能据此放宽保护。51条达到下界，也仅证明在当前选定节点图和该代价指标内最优，不能推导连续平面、其他扩充图或整轮比赛全局最优。

唯一更快例子为比赛地图区1无障碍“前往二维码板”：原模型4.82s，相同骨架、起终位置和航向下，把提前转头距离换成60mm后为4.78s，完整车体及相邻帧扫掠通过，最长横移不超过500mm。只相差两个50Hz模型步长，不是实车提速结论。

本轮按用户要求核算并保存候选，**没有自动把审计候选替换成运行路线**。结果新增`skeleton_points`、`search`及`optimality.proven=false`，可核查实际图阶段、展开次数、代价与最优性限制。
