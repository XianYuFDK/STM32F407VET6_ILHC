# v2.1.18 OPS异常诊断补充

当前通信为JDY-31蓝牙SPP，保留115200波特率、CRC1完整24通道50Hz遥测。此次增加诊断记录，不改路径、控制增益、通过门或OPS保护阈值；CCAPS仍为8。

23:12实机运行在TRUN约4.99秒后被固件以17取消。原日志能确定取消来自OPS保护，但无法区分会话号变化、时间戳回退、IMU重新建立航向或接收故障。本次更新让下一轮记录具体原因；历史日志不能补回这些缺失字段。

## 更新与使用

烧录`MDK-ARM/build/STM32F407VET6_ILHC/STM32F407VET6_ILHC_v2.1.18_OPS_DIAG_CCAPS8.hex`，并重启上位机。正常启动实机运行即可，日志仍位于`records/runs/`，运行完成、取消或手动STOP后自动结束。旧固件仍可使用上位机，但不会产生新增OPS诊断。

`events.jsonl`同时保留原始USART1接收文本`RX_TEXT`和解析后的`OPS_DIAGNOSTIC`事件。原始USART1字节记录也保留。运行结束后使用`analyze_run.py <运行目录>`，报告中的`runs[*].ops_diagnostics`包含故障现场和周期快照。此处不是对USART2所有OPS原始报文的逐帧录制。

## 数据字段

所有数字用十进制整数传输，避免会话号、时间戳经浮点通道丢失精度。

|报文|按顺序排列的字段|
|---|---|
|OPSE|事件ID、原因掩码、STM32 tick、旧会话号、新会话号、旧OPS时间戳、新OPS时间戳、OPS序号|
|OPSX|事件ID、OPS flags、帧间隔ms、有效定位年龄ms、排队报文年龄ms、HAL UART错误掩码、CRC错误累计、接收溢出累计|
|OPSD|STM32 tick、会话号、OPS序号、OPS时间戳、flags、定位有效标志、有效定位年龄ms、CRC错误累计、格式错误累计|
|OPSR|STM32 tick、UART错误累计、最近UART错误掩码、接收溢出累计、过期报文累计、接收重启失败累计、诊断队列丢弃累计|

OPSE与OPSX按事件ID关联；OPSD与OPSR属于同一次冻结快照，共用tick。缺失半条故障报文标记`complete=false`，不会用后续快照伪造故障现场。周期flags反映驱动最后发布的有效帧，OPSE/OPSX帧故障现场保留触发帧flags。

|原因位|含义|
|---|---|
|1|OPS会话号变化|
|2|OPS时间戳回退|
|4|有效帧间隔超过200ms|
|8|协议V2切换为V1|
|16|IMU重新建立航向（IMU_REBASED）|
|32|USART2接收重启失败|
|64|OPS接收队列溢出|
|128|OPS接收队列故障|
|256|排队报文年龄超过200ms|
|512|USART2硬件错误|

掩码可组合。HAL UART错误位：1校验、2噪声、4帧错误、8溢出、16 DMA错误。CRC等字段是累计计数，需要比较前后增量。

## 时序、开销与限制

异常现场进入4条固定容量FIFO，中断中只复制整数，不格式化字符串。首条故障的OPSE、OPSX优先于取消TSTAT发送，以便上位机关闭日志前保存现场；发送忙或失败不消费队列。发送完一对后让轨迹回复先发送，连续故障不会饿死取消状态。故障超出容量时计入`diagnostic_drops`；无线传输仍可能丢失，不能保证所有现场完整抵达。

正常状态每2秒发送一对低优先级快照，不追加逐帧诊断。文本每条不足100字节，与原遥测组合不超过212字节DMA缓冲。日志仍在后台落盘，待机不创建运行日志；实机的新增报文不会在模拟中伪造生成。

8个真实C专项和38个PC/Qt日志、解析专项通过，包括故障报文忙/失败重试、持续故障下取消回复公平性、混合分片解析和取消前落盘。EIDE构建0错误0警告，Flash 82276字节、RAM 97472字节。首次遥测测试提取器不接受uint16_t返回函数，修正夹具后复跑通过；初始失败日志保留。验证明细见`ops_diagnostics_checks_20261006.json`。
