# OPS短暂串口错误恢复

23:44日志确认USART2帧错误FE导致出库后取消：会话号4→4，最近有效定位仅1～2ms，但旧固件把UART错误设置成`session_changed`，立即取消整轮。此次修复区分传输错误和坐标系变化，仍使用JDY-31蓝牙SPP及完整24通道50Hz遥测。

## 新行为

收到错误时立即使旧定位失效，通知控制任务输出零速，并由通信任务中止残留DMA、清除UART标志、清空旧接收队列并重挂接收。在任务恢复前屏蔽接收错误中断并清标志，同一恢复过程的重复错误回调合并现场，错误累计计数仍保留。

具备有效V2定位、非零会话号、且无已知坐标系变化时，可以进入短时恢复。期限从错误前最后一个有效定位的接收时刻起算，超过200ms就取消；重试、重复帧、CRC错误或缺少IMU在线等无效报文均不能延长期限。

续行必须收到校验正确、同会话、序号及时间戳均向前推进的新V2定位，时间戳前进量也不超过200ms，且没有IMU_REBASED。正常序号/时间戳回绕用模差处理。真实会话变化、时间倒退、IMU重置、旧V1无会话保障或无法及时恢复，仍停车并取消。接收队列溢出、过期等既有硬保护不放宽。

暂停时保留批次、点位、进出弯状态及目标，不推进路径；清零速度斜坡、停稳计时和旧控制回复，更新控制时钟，避免恢复后因一次暂停产生`dt>100ms`假故障。最后一次定位仍保留用于检查恢复后的位移/角度跳变，50mm/15°等原有保护不改；总180秒运行上限不延长。终点恢复后必须重新满足完整200ms停稳窗口，已取消批次不能被恢复。GOTO的短时恢复同样保留目标。

如果错误在轨迹计算期间抢占，提交速度前再次核验定位在线，禁止计算出的旧速度提交；OPS帧发布时检查错误代次，并在短临界区内提交，禁止被错误中断打断的旧包重新宣告在线。

## 日志与界面

保留OPSE/OPSX故障记录与OPSD/OPSR周期快照，新增原因位：

|位|含义|
|---|---|
|512|USART2错误，记录HAL错误掩码|
|1024|接收恢复超过最后有效定位的200ms窗口|
|2048|接收已恢复，允许续行；这是恢复通知，不表示取消|

恢复通知的间隔字段表示当前STM32 tick距错误前有效定位接收时刻的间隔，UART错误字段保留本次恢复过程累计的错误位。其前后时间戳字段沿用驱动当前元数据快照，不能当作额外的逐字节接收录制。仍按事件ID关联，缺半条明确标记。

上位机错误17改为“OPS保护：坐标系变化或接收恢复失败（详见OPS诊断）”。运行日志在恢复过程中继续记录，仅真正完成、取消或用户STOP时结束。路线算法源码、36份缓存及CCAPS8保持不变。
