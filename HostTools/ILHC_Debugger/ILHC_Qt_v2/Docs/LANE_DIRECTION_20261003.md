# 比赛车道形状与长横移修复

用户指出：顶部轨迹有浅斜线和弯扭，车头几乎不变化，原料区到粗加工区1630mm全程横移。
本轮仅修改PC比赛规划，未连接STM32。初始车头仍是界面0°朝+Y；绿色箭头是运动方向，白色尖端是实际车头。

## 原因与处理

- 旧候选优先保持车头，仅在绕路超过直线距离1.3倍时比较其他朝向，普通导航的横移代价没有进入比赛选择。
  现在长横移也触发两个正交车头的比较；固定车头候选仍有超过500mm连续横移时，继续比较圆弧中随切线转头的前进、倒退方案。
- 路线选择使用真实控制器预演时间、出发转头估计时间和方向代价。沿用普通导航的前进1、倒退1.15、横移1.8；
  斜行用纵向/横向加权向量范数，轨迹按真实车头和运动切线进行弧长积分。
  删除没有实际发生的每站恢复原航向代价，下一站继续使用上一站实际结束航向。
- 长度至少500mm、偏离横纵轴小于12°的浅斜边增加形状代价；捷径不会主动生成这种长边。
  浅斜边尝试短接近段连接直车道，每个替代线段重新检查完整矩形扫掠，弧线全部半径失败则退回原候选或明确fallback。
  设备或障碍确实需要浅斜线时仍允许安全候选，不用画直线掩盖真实轨迹。
- 出入库保留经整车检查的斜行及安全L形fallback。中间采样点不停稳；必要的站点转头仍是显式、经整车检查的动作。
- 比赛JSON增加motion_metrics，记录前进/倒退/横向分量、最长连续横移和方向等效代价；selection记录候选实际车头与代价。
  反向圆弧的导出元数据也使用反向实际车头。

方向权重是规划偏好，不是实车测定速度，模拟器仍按250mm/s平移上限、120°/s转头上限积分。
旧版将长横移与直行按相同速度计时，所以减少横移、加入实际转头后，本轮理想PC总用时增加；不能声称本次已缩短实车比赛时间。
策略仍有搜索预算、局部半径选择和逐路段候选选择，不保证整轮全局最优。
