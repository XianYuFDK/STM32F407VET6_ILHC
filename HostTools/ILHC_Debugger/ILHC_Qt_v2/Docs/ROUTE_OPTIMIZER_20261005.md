# v2.1.4 路线搜索与控制候选优化

实机点击、正常回库、模拟和实机整轮的关键坐标规划均接入新优化器。重启上位机使用v2.1.4，本轮不需要重新烧录固件。

## 选择目标

先最小化**通过完整安全预演的骨架长度 + 每次折弯120mm**；同代价时选择模型用时更少的控制程序，随后比较实际方向代价和实际行驶长度。120mm是折弯权重，不是额外实测距离。

三种车头模式、九组通过范围/提前转头/离站参数均参与比较，等价程序去重。不会找到首个安全候选就直接返回，也不再用前缀访问名额裁掉新优化器的路径。

旧算法只生成已验证的可行上界。新A*用包含前驱方向的反向Dijkstra计算余下距离和折弯代价下界；按代价枚举骨架，并剪除可证明高于当前上界的分支。在原车道、增加侧移连接和细化障碍车道三个图中分别搜索。共线点只在实际存在直连边时合并，不凭简化创造新连接。

通过上界和下界比较证明：未搜索的路线不能更便宜，所有同价路线和控制候选也已经比较后，才标记`optimality.proven=true`。

## 验证结果

两种地图（默认地图自动补competition、比赛地图）、无障碍/两障碍、两启停区，共8组整轮、64个行驶路段：

- 64个路段均完成上述限定范围和目标的最优性证明。
- 相对于同一起始姿态的旧算法上界，20个路段降低骨架代价，最大降低7.22%。
- 8组整轮模型总用时全部下降，节省1.18～4.14秒，即2.00%～4.44%。
- 所有整轮完成12次抓取、12次放置并返回；完整矩形及相邻姿态扫掠、整批坐标量化预检均通过。

| 地图/障碍 | 启停区 | 原整轮模型时间 | 新整轮模型时间 |
| --- | --- | --- | --- |
| 默认/无障碍 | 1 / 2 | 59.00 / 59.00s | 57.36 / 57.82s |
| 默认/两障碍 | 1 / 2 | 92.54 / 94.90s | 88.76 / 91.60s |
| 比赛/无障碍 | 1 / 2 | 59.00 / 59.00s | 57.36 / 57.82s |
| 比赛/两障碍 | 1 / 2 | 93.32 / 94.90s | 89.18 / 91.62s |

例如区1前往二维码，从1100mm骨架代价降到1056.30mm，模型用时4.82→4.20秒。

真实`trajectory_buffer.c`经本地编译执行8轮（两区×无/单/四/两障碍），全部DONE，逐帧车体/扫掠、站点、PASS不停稳、零TRESUME均通过；并验证CRC、参数快照、映射、STOP、定位失效、偏差与旧能力拒绝。这是离线C执行器回放，不是实车测量。

最终6组核心自检、307项无GUI回归、53项真实Qt地图/实机入口回归、5项C专项全部通过，各进程退出0；最后15项搜索/预算/取消复核通过。初始回归发现点击8秒预算错误地作为取消，以及一个异步测试仍只等5秒，修复后final日志均通过。

## 计算预算和证明范围

每个图至多展开12000个前缀，整体至多比较96个不同骨架。耗尽预算保留已通过完整预演的最佳路线，证明标志为false；未得到安全路线则拒绝运行。

点击规划保留8秒默认计算预算。预算耗尽与用户取消分开：已经存在安全方案时返回当前最佳方案；没有安全方案仍拒绝。STOP/地图/参数/会话变化属于取消，绝不能因保留上界重新获得执行权。整轮规划在后台比较全部路段，可按停止取消。

加入相同程序的成功/失败预演缓存（每次规划独立，参数和约束进完整键）及有界姿态扫掠缓存，减少重复计算。现场不同地图和CPU负载会改变规划时间；扩大候选比较比旧算法需要更多计算。

**证明限定于三个有限车道图、无重复节点的简化骨架、现有27组控制组合、既有安全预演及上述排序目标。** 这不是连续空间任意路线/任意控制量的全局证明，也不证明整场任意站点航向组合的最快时间。全局连续最优和全局时间最优字段保持false。此前51/64结果比较的是放宽控制限制后的图下界，与本轮安全候选最优性证明不是同一个指标。

完整车体尺寸、安全裕量、横移限制、75mm骨架偏差门、停止/停稳要求、底盘七参数回读、量化和运行保护均保持。
