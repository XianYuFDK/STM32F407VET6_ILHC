# 35电机X固件通信诊断（2026-10-02）

用户仅连接35电机，机械目标、原始目标、回零都无反应，并确认驱动菜单设置正确。未接入本机可用的实物CAN链路，因此没有实测回包，不能把软件回归等同于电机已经恢复运动。

## 已确认的软件问题

- S35MOVE/S35RAW按钮输出与STM32串口解析接口匹配，没有发现命令名称错配。
- X固件速度单位为0.1RPM；原驱动把上位机填写的RPM原样发送，速度实际小十倍。现已乘10转换，并限制到3000RPM。
- 原始位置为X固件角度整数，默认单位0.1°，原界面“绝对位置计数”标签不准确。现已更正，要求S_PosTDP=Disable。
- 电机CAN回包原先仅在STM32缓存，没有转发到上位机。现提供入队、CAN提交/失败、超时与原始回包诊断；读取状态和使能是显式按钮操作。
- 同一个串口read中，文字行后接二进制遥测可能擦掉已完成的文字行。现改为遇换行即提取，保留重复的步进诊断。
- 当前代码使用CAN2 PB5/PB6，文档按此配置说明；实物接线仍需核对。

## 实机检查顺序

1. 烧录本次生成的配套固件，再启动本目录run.bat，使用真实串口连接。
2. MCU侧应为PB6→CAN收发器TXD、PB5←RXD；收发器H/L侧连接电机CANH/CANL。
3. 驱动菜单P_Serial=CAN1_MAP、CAN_Baud=1000000、ID_Addr=1、Checksum=0x6B。
4. 点击35读取状态，等候页面和日志中的回复。仅看到TX日志而没有QUEUED，需要检查串口连接及板上固件是否包含本次修改。
5. CAN_SUBMITTED后NO_REPLY：核对收发器接线、模式、供电、H/L、总线终端及实际速率/地址；该提示不能证明CAN报文已经送达。
6. CAN_TX_TIMEOUT：邮箱长时间忙，可能没有节点ACK或总线异常。CAN_TX_FAILED：HAL提交失败或CAN状态不可用。
7. 状态回包3A xx 6B证明驱动通信有回复。bit0=0时可显式点击使能锁轴后再读状态；bit3=1表示堵转保护，需要排查机械/保护原因。E2是参数或执行条件不满足；EE是指令格式错误。02仅表示命令确认，9F表示驱动返回动作完成。

接口不自动触发校准、回零或运动。STOP/CANCEL仍只撤销步进待发请求，不能停止已经下发的步进运动；本次没有宣称验证了硬件停机行为。
