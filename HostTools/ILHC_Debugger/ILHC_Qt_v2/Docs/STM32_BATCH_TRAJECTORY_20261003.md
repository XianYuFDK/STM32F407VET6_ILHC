# STM32完整比赛整批轨迹（2026-10-03）

当前为自动跑图测试。上位机在发车前生成并上传完整比赛的全部路段。STM32 SRAM保存整批点表，全部接收、CRC和结构校验通过后，才接受一次TRUN开始本地连续跟踪。7处站点只用STOP门，停稳后STM32自动继续缓存中的下一段，不进入WAIT，不发送TRESUME，不需人工确认，不重发路径。串口使用分包和接收应答；“一次上传”指完整批次在运行前传完，不要求一次串口write。

2026-10-04补充：点击地图/快速目标也使用本协议整批执行；不要求包含competition配置；2026-10-04用户要求直接采用当前地图，geometry_verified不再拦截执行。点击路径批次kind为STM32_POINT_PATH，stations/waits为空，execution_mode区分CONTINUOUS和STOP_TURN_FALLBACK。首点允许STOP（不得WAIT/ROTATE/ARC），连续200ms新鲜OPS停稳后再进行必要的初始转头，XY/s与下一ROTATE点一致。目标航向沿用界面选择，包含必要的最终转头STOP。当前AC5构建RAM92136字节，ROM61912字节，覆盖下方历史用量。操作见[点击路径接入](CLICK_STM32_RETURN_20261004.md)。

## 界面操作

1. 使用本次配套固件与Qt源码，重启旧上位机。加载含competition站点/两启停区配置及drivable白名单的比赛地图，录入当前障碍。按2026-10-04用户要求，直接使用当前地图几何，geometry_verified保留为元数据，不再作为上传门禁。
2. 连接STM32 USART1，115200/8N1。使能底盘，保持OPS定位在线，在所选启停区标定位置/航向。用户航向0°朝场地+Y（上），90°朝+X（左）；起点实际误差不超过5mm/3°。上传不会自动ZERO或移动到起点。
3. 输入预设任务码，点击“实机自动跑图：整批上传并运行”。预检完整车体、圆弧、转头和整数化后的整批扫掠，之后进行容量握手、整批上传和校验。预检/上传期间车辆停车等待。
4. 自动经过二维码站、第一批原料→粗加工→暂存、第二批原料→粗加工→暂存；7处站点达到位置、航向、停稳条件后自动继续，无需发送任何作业完成信号。界面移除“作业完成，继续”按钮。
5. 自主返回所选启停区，最终位置/航向/停稳满足后DONE。当前只验证路径及启停，不实际扫码、抓取、放置或完成塔吊任务；输入码用于预设流程和记录。

清路径、重规划、地图/障碍/标定/任务码/启停区变化、手动接管、STOP、断开连接都会取消整批并清除排队点/启动命令。取消后不能恢复旧批次。可以“导出实机批次”保存JSON点表、CRC、坐标映射、站点清单及当前状态。

## USART1 ASCII协议v1

每行以LF或CRLF结束，整数，不带空格；批次id为1..4294967295。所有点必须按index从0递增，匹配的重复点不追加；不同内容重复或漏序拒绝。接收窗口3点，PC等ACK推进下一窗口，不等车辆完成路段。

| 命令 | 含义 |
|---|---|
| TCAPS | 固件回复TCAPS 1 4096 3 |
| TBEGIN=id,count,map_version,CRC8HEX,margin_mm | 创建完整接收批次，点数2..4096，裕量5..100mm |
| TPOINT=id,index,x10,y10,yaw100,s10,flags | OPS零点坐标0.1mm，航向0.01°，累计弧长0.1mm |
| TCOMMIT=id | 点数、CRC、采样/停靠/转头结构完整校验 |
| TRUN=id | 仅READY允许启动，本轮发送一次 |
| TRESUME=id,wait_index | 预留给未来真实作业WAIT，当前自动跑图不发送 |
| TSTATUS=id | 查询批次状态 |
| TABORT=id | 取消当前匹配批次 |
| STOP | 原有停车命令，同时取消批次 |

TSTAT id state received cursor s10 error为状态应答。state：0空闲，1接收，2任务校验，3READY，4运行，5等待作业，6完成，7取消，8故障。error中文含义见hardware_trajectory.py的ERRORS。QUERY重复状态仍交付上位机，不被文字去重过滤。

flags位：STOP=1，WAIT=2，ROTATE=4，ARC=8。中间采样点不停车。当前站点STOP不带WAIT，连续200ms新鲜OPS满足停稳条件后任务自动继续；最终STOP后DONE。未来WAIT必须同时STOP。原地转头点与前点同XY/s，带ROTATE|STOP，前点也STOP；转头完成后继续已缓存路段。最后一点STOP且不能WAIT。

## 后续塔吊接口

make_match_batch默认station_mode='AUTO_ROUTE'，JSON中stations保存7处站点索引及清单，waits为空。仅未来接入真实机构时显式使用station_mode='WAIT_FOR_ACTION'，让站点带STOP|WAIT；这不改变整批路径预上传机制。

塔吊实际完成作业后调用Traj_CompleteStation(batch_id, point_index)。只接受当前批次、当前WAIT站点且未取消的请求；错误/过期站点、运行中或STOP取消后调用返回0，不能复活旧路径。下一控制周期仍验证定位、底盘、心跳和停稳条件后继续。本次仅预留完成接口，未接塔吊或驱动抓取。现有TRESUME复用同一完成门，仅保留协议兼容。

CRC32为IEEE标准，Python zlib.crc32相同，按全部点拼接的小端16字节记录计算：int32 x10、int32 y10、uint32 s10、int16 yaw100、uint16 flags（注意CRC/JSON的s、yaw顺序与TPOINT文本顺序不同）。JSON内point_fields明确字段顺序。接收中断只解析整数、存点、增量CRC；任务每周期最多校验64点。

## 坐标与跟踪

轨迹内部FIELD几何车头角+X=0°、+Y=90°，field_yaw_deg是实际车头，tangent_yaw_deg是行驶方向，倒退时独立。上传逆变换为OPS坐标：x=c*(field_x-ox)-s*(field_y-oy)，y=s*(field_x-ox)+c*(field_y-oy)，yaw=wrap(90-theta-field_yaw)。因此默认映射下用户0°朝+Y仍上传OPS yaw0，不能把几何切线当车头。

直线间隔≤20mm；实机圆弧额外保留≤3°角采样。全局20mm网格与弧角采样出现相同量化s时合并近点，拒绝零弧长非零运动。每个传输点和相邻扫掠重新检查完整280×260mm矩形+裕量，任何失败拒绝整批。

STM32根据真实OPS位置投影到当前STOP门之前的折线，进度单调，使用100mm前视参考，前馈采用当前投影的几何增量；车头独立插值、最短角跨±180°。速度≤250mm/s，角速度≤120°/s，旋转弧线降低平移速度。世界速度按现有轴序转车体后送现有四轮UART4速度接口，支持前进、倒退、横移与斜行。

STOP门要求位置<5mm、航向<1°、OPS测量速度≤5mm/s、角速度≤2°/s，并连续200ms新鲜OPS采样满足。只有新定位帧增加停稳时间，不能用重复遥测或目标速度0假装停稳。最终DONE、WAIT、取消/故障通过已有底盘停车门禁，失能时不发送会重新使能电机的零速帧。

本地保护包括：上位机心跳1秒、上传无进展3秒、OPS新鲜度200ms/有限值/会话变化、位置或航向跳变、任务调度>100ms、运行及WAIT合计180秒、5秒无进展、WAIT期间位置/航向漂移、实际轨迹偏差超过规划裕量。规划裕量供跟踪误差消耗，本地中心/车头联合偏差预算保留1mm；主机检查实际矩形+剩余1mm与地图，版本改变立即取消。STM32未缓存整张地图，依赖主机完整预检与本地偏差预算，不能在车上自行重新避障。应答与遥测交替，上传不饿死遥测。

## 内存、构建与验证边界

点表4096×16=65536字节，不写Flash，不占任务栈。AC5当前构建RAM 92136字节（约90KB/128KB），ROM 61440字节；EIDE及Keil均加入trajectory_buffer.c。固件位于MDK-ARM/build/STM32F407VET6_ILHC/STM32F407VET6_ILHC.hex。

MECANUM_ROTATION_LEVER_MM默认270mm，表示轮中心前后半距+左右半距，实车须按实际轮距标定；现有0.238 RPM/(mm/s)换算也需实车核对。UART4四轮阻塞发送和电机响应会影响真实调度/误差，离线积分不能替代实车验证。
