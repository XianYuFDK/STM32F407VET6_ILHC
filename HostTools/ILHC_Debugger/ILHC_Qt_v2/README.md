## 先启动

1. 把本包解压到一个新目录，保留整个 `ILHC_Qt_v2` 文件夹。不要只覆盖 `main.py`，新增的几何模块和地图 JSON 也必需。
2. Windows 双击 `install_windows.bat`，或者执行：

   ```bat
   python -m pip install -r requirements.txt
   ```

   本次新增 **Shapely 2.x**，用于完整车体扫掠、多边形合法区域、孔洞与连续碰撞检测。没有改成 ROS，也不需要修改 STM32 固件。
3. 双击 `run_simulate.bat`，或：

   ```bat
   python main.py --simulate
   ```

4. 进入“比赛地图”，保留“点击地图 = 规划路径”和目标航向“保持当前”。模拟器现在从静止的 OPS 零位开始，不再自动绕圈。
5. 点击“暂存区”“粗加工区”或地图空闲处。后台计算完成后显示路线及航点台账；这一步不发车。
6. 确认当前演示几何及起始车头与首段切线一致后点击“仿真行驶”。模拟器连续跟踪直线/圆弧，只有最终STOP停稳；再按该按钮、清路径、重新规划或STOP立即取消跟踪。

未连接串口或模拟器时，可从选定启停区进行**离线预览**；离线计划不能直接拿来执行，开启模拟/切换链路后须重新规划。

## 两个必须知道的限制

### 地图不是已核实的赛场灰色车道

`navigation_map.json` 明确标为 `geometry_verified: false`。默认只沿用上传版的2400×2400外框和固定障碍；全矩形允许区域只是**演示场地**，不是比赛灰色车道的确认数据。

已经实现 `drivable_polygons` 白名单（支持多个区域、合并、孔洞），但真实车道坐标必须来自你的场地图/测量，不能猜。

“加载行驶区域”读取 JSON。地图上红色半透明区域是白名单以外的区域，绿色虚线为白名单边界，规划障碍以新叠加的轮廓为准。原先的设备名称和底图仅作为参考。加载地图、改标定、改裕量/网格或控制模式都会使旧计划失效。

即使用户把 `geometry_verified` 设成 `true`，**本版仍不解锁实车自动导航**。

### 当前执行要求连续安全轨迹

界面的“额外裕量”现在是在**280×260mm整车矩形之外**再加的安全预算，默认10mm。设为0也不会忽略车体。这个280×260尺寸沿用上传代码，未擅自换回聊天中提过的270×250；实车应按相机、塔吊、线束等完整外形重新核实。

计划初始航向来自实际车头，碰撞模型保留实际角度。可平滑的90°角点生成圆弧，整条Trajectory
重新按切线航向做矩形车体复检。仍保留TURN、真实直角或失败fallback时拒绝连续执行。
实际起点须在轨迹起点5mm内、车头在初始切线5°内；起点未对齐时需调整后重新规划。

旧 `core.plan_path(..., pad=150)` 兼容接口还在，但在不传 `footprint` 时只是膨胀模型参考，`execution_safe=False`，不能当作整车可执行许可。

## 原料区：按钮不再写死坐标，按几何现算

旧“原料区”按钮写死的布局目标 `(1200,2200)mm` 离圆盘表面只有 90mm，而 280×260 车体轴向要
140/150mm、斜向（(150+140)/√2）要 205mm——它是**非法停车位**，点它必然被整车校验拒绝。
这个拒绝是正确行为（`tests/test_navigation_safety.py::test_default_material_goal_rejected`
锁住了它），但按钮本身不该指向一个停不下的坐标，所以该表已删除，改由几何现算。

现在 `core.QUICK_ANCHORS` 只记功能区锚点与“由功能区指向场内”的方向；点击按钮时按
**当前航向 + 当前额外裕量**现算合法接近点（`core.approach_target`，判据是车体外缘净空
≥ 站立距离 `APPROACH_STANDOFF_MM`）。算出的点会写进日志、画在地图上并显示在侧栏，
**不是**静默把终点换到附近；算不出就明说，并把“合法但净空不足”的点作为**建议**列出来。

默认（航向 0°、额外裕量 10mm）下原料区得到布局 `(1200,2100)mm`，即用户显示坐标 `(15,105)cm`，
与上面提到的演示接近点一致；航向斜置或裕量加大时它会自动再让开（如 45°、裕量 60mm 时为
`y≈2010`）。它仍不是已标定抓取位，机械作业位置需现场标定。

## 修复内容

- 真实起终点通过带代价且经过检查的连接边接入网格，不再替换首尾格点后跳过检查。
- 每一条网格边、路径首段/末段、只有两个点的路径及拉直后的每一段都检查连续碰撞。
- 网格生成使用 floor，不会生成2400mm场地外的2450mm节点；整车和安全裕量也不能越界。
- 平移使用当时航向的矩形扫掠，转向使用相邻采样姿态凸包加误差外扩；白名单先合并后检查，支持非凸区域/孔洞。
- 圆障碍使用真实半径距离判定，不用稀疏采样或内接多边形放大误差。
- `min_clearance` 改为精确的车心线到障碍距离；另有整车外缘净空和边界距离，不再显示“任意航向都能过”。
- `rects/circles` 自定义地图与净空计算使用同一份数据；空障碍、单点路径、NaN/Inf等输入明确处理。
- Qt 地图点击在单工作线程计算；带请求/版本标记和取消标记，旧结果不能覆盖新计划。
- 旧路径在新规划失败、标定、ZERO、OPSOFFSET、失能、链路和手动接管时失效。
- 仿真停止取消真实模拟目标，清理排队运动指令，命令消费与取消使用同一锁，防止迟到旧目标重启。
- 仿真到位匹配模拟器 epoch/goal_id，核对真实模拟位置、航向、完成状态和多个新帧；不使用旧 dev[] 推进。
- 执行前按真实起点复查；按旧协议精度量化坐标后再次检查，不静默钳位越界目标。

## 模拟障碍（φ50×100mm，最多 4 个）

演示用的临时障碍：顶视按 **r=25mm 的圆**参与碰撞，格式与地图自带障碍相同，但**不写进
`navigation_map.json`**（那是实测场地数据），只活在本次运行。

- **点击放置**：勾选「点击地图 = 放障碍」，此后点地图即放下一个（最多 4 个）；此时点击
  **只放障碍，不规划也不下发**。取消勾选，点击恢复为规划。
- **随机补齐**：在避开固定禁区、已有障碍、场地边缘和**车当前位置**（半个车对角线 + 半径
  + 20mm）的前提下随机放到上限；放不满会如实说明"随机尝试 N 次仍找不到合法位置，只放置了
  n/N 个"，绝不返回非法点。
- **会被拒绝的放置**：与固定障碍/已有障碍冲突、离场地边缘不足（半径 + 20mm 余量）、
  压在车上（否则之后每次规划都会以"起点：模拟障碍"失败）。拒绝时状态栏说明原因。
- **放了障碍，旧计划立刻失效**：障碍也进 `_navigation_signature`，仿真行驶前的复查
  （`_scene_for_context`）用的是同一套含障碍的几何，不会拿旧路径去跑已经变了的场景。
- 规划会绕开障碍；直接 GOTO 调试通道的直线检查也改为读同一份几何（地图数据 + 模拟障碍）。

## A* 升级：航向状态 + 动作代价（2026-09-29）

规划状态从"格"升为 **(格, 航向)**：车头方向成为搜索的一部分，路径可以"绕路换朝向"。

- **动作与代价**：前进 1.0、后退 1.15、横移 1.8（每毫米的系数）；原地每90°转向180mm等效
  （180°记两次）。A*输出Manhattan骨架与原动作台账，后处理生成安全圆弧及连续Trajectory。
- 侧栏新增「**道路禁横移**」（默认关；勾上后换方向必须靠原地转向；地图 JSON 里的
  `strafe_polygons` 作为操作区仍允许横移）与「**转向等效代价**」（默认 180mm，调高＝尽量别转向）。
- 规划结果给出 **x, y, heading, action** 逐步台账（同向直行合并、转向零位移成步），并给出
  横移总距离与转向次数；`search_cost`（加权）与逐条台账的代价之和必须一致。
- **仿真行驶连续跟踪**：执行已复检的直线/圆弧切线轨迹，仍含原地转向或失败fallback时拒绝启动。
- 起点/终点若贴着墙角（启停区中心离两墙各 150mm），原地转不动 ⇒ 勾了「道路禁横移」会报
  "没有合法网格接入"并提示先把车移开。这是物理正确的拒绝。
- 回归：`python run_tests.py`（88 用例）、`python run_tests.py --qt`（88 用例）。

## 视觉跟踪页（协议 V1.1）

侧栏最后一页「视觉跟踪」：6 色启动按钮（`VTRACK=1..6`）、停止（`VTRACK=0`）、刷新回读，
以及 6 个可调参数行（`VCONF`/`VKPMM`/`VDBMM`/`VDBPX`/`VMIN`/`VMAX`）。

- **会驱动底盘**，与 GOTO/键盘手动同级：启动会取消 GOTO 与键盘手动并停车，STOP 也会自动
  停止跟踪。四轮未使能时固件回 `ERR WHEEL DISABLED; WHEELEN FIRST`，有其它动作挂起时回
  `ERR VTRACK BUSY`。
- 这 6 个参数是 **RAM 参数**：可设置、可 `GET` 回读，但**不存 Flash**，掉电回固件默认值
  （`VDBMM`=2mm、`VMIN`=8、`VMAX`=60）。界面上的默认值与固件 `vision_track.c` 的编译期
  默认值一致，改任何一边都要同步另一边。
- **24 通道遥测里没有视觉位**，所以这 6 行只能靠 `GET 名称` 的文字应答点亮「回读」栏。
  进页面时会批量刷新一次；参数行的「发送」也会在写入后立刻补读一次。
- 页面看不到实时 `EX/EY/FLAGS/CONF`（那些只在工控机自己的画面里）。也没必要自己发
  `VTRACK=0`——固件的 STOP 已经会停跟踪。

排查"发了命令没反应"时注意：`名称=数值` 这种参数回读行在解析层就被分流出了日志
（`core.PARAM_ECHO_RE`），所以别拿日志里有没有这行判断固件是否响应。如果回读的名字在界面上
没有对应参数行，日志里会出现 `回读 X=Y（界面无该参数行）` 而不是静默丢弃。

# 2026-10-02：X固件35电机通信诊断

35/28步进页新增“读取状态（不运动）”“使能电机（锁轴）”及真实驱动回复显示。需同时更新配套STM32固件，旧固件不支持S35STATUS/S35EN。固件已在Keil目标STM32F407VET6_ILHC编译通过（0错误、0警告）；本次上位机95项Qt/串口测试及CAN协议回归通过，尚未烧录或验证实机回包。

当前总线为CAN2：PB6→收发器TXD、PB5←收发器RXD，1Mbps；35节点地址1，28节点地址2。电机菜单P_Serial=CAN1_MAP、Checksum=0x6B。CAN1_MAP是电机驱动菜单的选项名称，STM32端使用CAN2。

先点击读取状态，页面显示STM32请求入队、CAN邮箱提交、驱动原始回包或500ms无匹配回包。CAN_SUBMITTED只说明报文入邮箱，不代表驱动执行。状态回包3A xx 6B中bit0为使能、bit3为堵转保护；E2表示参数/条件不满足，EE表示格式错误。模拟模式不产生硬件回复。

原始位置字段是X固件角度整数（单位0.1°），须将S_PosTDP设为Disable；速度字段为实际RPM，固件发送CAN时乘10。转速限1–3000RPM；35机构速度限1–100mm/s，28限2–5662mm/s。原车机械换算系数仍需实测标定。默认35高度203mm、28半径120mm和原始角度0都对应零点，已在零点时重复执行不会运动。

修复了串口文字回复与二进制遥测同批到达时丢文字行的问题；重复的步进回复每次都会显示。详细修改和排查步骤见[Docs/STEPPER_X_DIAG.md](Docs/STEPPER_X_DIAG.md)。前文原有测试记录保留为历史记录。
