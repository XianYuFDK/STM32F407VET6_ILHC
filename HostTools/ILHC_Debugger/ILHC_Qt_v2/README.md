# ILHC Control Station v2.0 (Qt)

当前统一坐标（2026-09-17）：`+X=车左`、`+Y=车头`、`+Z=逆时针`。
Qt 显示、地图、`MANUAL/GOTO/OPSOFFSET` 和固件内部都直接使用该轴序，
不再保留“前后/左右”本地顺序或内外交换层。

连接真实串口后自动发送一次`VOFA`恢复24通道遥测。固件在ZDT文字调试或CAN启动失败后
可能关闭二进制遥测；PING不切换输出模式。连接后手动进入文字模式时，可在命令终端发送
`VOFA`返回波形。恢复遥测不等于OPS已在线，位置全零需另查OPS接收链路。

2026-09-16 遥测静默修复：实车反馈"连上后坐标一直不刷新、之后串口再也收不到数据"。
抓到 COM14 原始数据确认固件只发了 `ERR CAN START FAILED; CAN DISABLED; USART1 AVAILABLE`
之后就不再输出——CAN1 启动失败时固件开机即进入文字模式（`debug_usart.c:1040-1044`），
24 通道遥测被整体关闭，只有 `VOFA` 能恢复；而旧版上位机只在打开串口那一刻发一次 `VOFA`，
板子在上位机已连接时复位（或那次 `VOFA` 落进固件 `OPS_Init` 约 1.3 秒的启动空窗）之后就
再无补发机制，表现为永久 0 字节。现在：

- 超过 1.5 秒收不到可解析帧会自动补发 `VOFA`（每次中断最多 6 次，收到任一帧即重置计数），
  复位后 1.3 秒的启动空窗也能覆盖，无需手动干预；
- 固件的文字应答/错误行不再被解析器丢弃，会以`固件文本: …`显示在日志里，
  含 `ERR`/`FAIL` 的行按警告着色——**CAN 启动失败这类报错以前是完全看不见的**；
- 日志里出现`上位机: … 已补发 VOFA 恢复波形`即表示上位机正在尝试抢救遥测。

如果补发到上限仍无遥测，按顺序检查：串口是否选错（本机可能有两个 CH340）、板子是否真的在
运行（OLED 显示 READY 只说明启动早期，它在 CAN/OPS 初始化之前就写了）、以及固件报出的
CAN 失败原因。另注意 bxCAN 进入 NORMAL 模式不需要总线上有其它节点，`CAN_Start` 失败通常
不是 CANH/CANL 接线问题。

## 连续键盘控制更新（2026-09-13）

2026-09-17 坐标统一：`manual_vector` 现与 `MANUAL` 完全同序，均为
`(X=车左, Y=车头, Z=逆时针)`；`GOTO`、`OPSOFFSET` 和遥测也原序使用同一轴。
三个反向开关只作为键盘手动兜底，默认全部关闭，顺序为“左右/前后/旋转”。
验收：W 向车头、S 向车尾、A 向车左、D 向车右。

按住期间使用50ms精确定时器续发MANUAL；方向变化立即更新目标，不重启续发计时器。
待发MANUAL合并为最新一条，优先于普通参数，STOP仍使用更高优先级紧急队列。
串口只读取当前已有字节（单批最多2048）；无数据时读1字节，超时10ms，降低控制延迟。
仅绘制可见页面（主界面当前页 + 已拆出的独立窗口）的波形或轨迹，减少隐藏页面对GUI线程的占用。
保留松键、失焦停车和固件350ms手动命令超时，不提供松键后继续运动的锁定模式。
这些改动优化主机调度，不代表已经实测解决机械顿挫；设备固件本次未修改。

## 独立窗口与窗口置顶（2026-09-18）

每个页面都能单独拆成独立窗口，方便一边看波形/地图、一边在别的窗口上调参：

- 页面标题右侧的「独立窗口」按钮：当场拆出该页
- 左侧导航按钮右键菜单：拆成独立窗口 / 取回主窗口 / 窗口置顶 / 取回全部独立窗口
- 独立窗口标题栏：`置顶`（可勾选，让窗口保持在其他窗口之上）和`取回主窗口`
- 关闭独立窗口等于取回：页面回到主界面原来的位置，拆出时主界面显示占位卡

独立窗口是普通顶层窗口，不挂主窗口做父级（Windows 的 owned window 会永久压在主窗口上面），
所以点击主窗口或任务栏即可把独立窗口换到下面，只有勾选`置顶`时才会强制保持在最上层。
也因为不带父级，独立窗口自己复制一份主窗口样式表来保持外观，并在关闭主窗口时统一收回。

页面控件是同一个对象换父窗口，不是复制窗口：信号、定时器、串口命令队列、
键盘遥控状态全部保持，拆出后仍能正常下发参数和续发`MANUAL`。
主界面只画当前页，拆出去的页面仍按可见页面继续刷新波形/轨迹。
在独立窗口里做键盘遥控时不会因为主窗口失焦而误判为“离开应用”停车；
焦点离开该独立窗口（点击其他程序）仍会按原逻辑松键停车。
拆分状态只保存在本次运行内，重启上位机后所有页面回到主界面；
固件协议和通信代码未改动，不需要重新烧录。

## 底盘手动控制（2026-09-10）

Qt「底盘调参」手动区现改为游戏式键盘遥控（2026-09-12）。连接或开启模拟后点击「进入键盘遥控」，W/S前进后退、A/D左右平移、Q/E逆/顺时针旋转，方向以车体为准。支持W+A、W+Q等组合，按住Shift为30%低速，空格停车，Esc退出。相反按键互相抵消，斜向平移归一化，避免总平移速度增加。界面实时高亮按键；仅键盘区获得焦点且已启用时接收控制键，不拦截命令终端输入。

默认平移60 RPM、旋转30 RPM，可调整1–300。这些是轮速混合分量，旋转值不是角速度，不使用GOTO的XVMAX/ZVMAX。

地址按俯视、车头朝上：左前1、右前2、左后3、右后4。实际转向沿用已有麦轮速度解算；第一次低速核对运动方向，可用「左右反向/前后反向/旋转反向」修正手动按键。这些选项仅作用于本次界面手动控制，不改变GOTO或保存到Flash。

协议：`MANUAL=X,Y,W`，X=左右速度、Y=前后速度、W=旋转速度（逆时针为正），严格三个整数，范围各-300..300，以换行结束；例如`MANUAL=0,100,0`为前进、`MANUAL=-100,0,0`为右移、`MANUAL=0,60,30`为前进与逆时针旋转分量叠加。界面 `manual_vector` 同样按 `(X,Y,Z)` 保存，直接发送，不交换。主机按住期间约50ms续发，固件350ms未收到有效MANUAL即在下次任务服务停车，PING不续期。无OPS也可手动运行。有效MANUAL取消GOTO，有效GOTO结束手动；STOP/ZERO取消手动。松开全部运动键或空格会优先发送`MANUAL=0,0,0`仅停止底盘，保留键盘接管；空格清空按键，需重新按下才能继续，忽略系统自动重复键事件。

进入遥控先请求STOP取消原有运动。Esc、点击其他控件导致失焦、切页、窗口失去激活、断开、关闭时退出键盘接管；正在运动时结束续发并请求STOP（也失能DM并取消28/35待发）。恢复焦点不自动恢复运动。线程或串口故障靠固件独立超时兜底。停车时间受现有任务周期、串口阻塞影响，不是硬实时保证。上位机显示的是发送请求，没有固件手动状态ACK。串口遥测保持24通道不变。

本次只更新Qt交互，复用现有MANUAL固件，无需为键盘新增串口协议。原版上位机仍可在终端发送MANUAL，其模拟器支持手动运动及超时。真实使用需要设备已烧录支持MANUAL的F407固件。本次测试不连接设备、不发送实际运动命令。


## OPS 安装偏心补偿（2026-09-10）

F407 的 `Hardware/ops.c` 默认安装偏移为统一坐标 `X=左60mm、Y=后-50mm`。
安装补偿协议 `OPSOFFSET` 继续使用 mm，不随移动/遥测改成 cm。OPS 原始帧实测
`+x_raw=车右、+y_raw=车头`，`ops.c` 只在内部映射为 `X=-x_raw、Y=+y_raw`；
界面、协议和固件控制器不再交换轴。

补偿由F407执行一次，不修改OPS板固件。公式：`中心相对位移 = 原始OPS位移 - (R(yaw)-R(参考yaw))*r`。首帧航向是未ZERO时的参考；建议上电保持静止并收到有效OPS数据后ZERO。ZERO保存原始位置和当时yaw，位置和航向同时归零；置零后 `Y` 向前增大、`X` 向左增大、`Z` 逆时针增大。`OPS_GetAbsolutePosition()`和`OPS_GetData()->frame`仍是原始OPS数据；未ZERO的`OPS_GetPosition()`也会补偿。`OPS_ClearZero()`切回绝对 X/Y/Z。`OPS_SetOrigin(x,y)`还会把当前航向设为 Z 零点。

### 上位机操作

1. 烧录本次 F407 固件，打开 Qt「底盘调参」顶部「OPS安装偏心补偿」。填写 `X 左右=60`、`Y 前后=-50`，单位 mm。两个输入框与 `OPSOFFSET` 完全同序，保存的 JSON 键 `x_mm`=X左右、`y_mm`=Y前后。
2. 点击「应用补偿并置零」。界面停止手动续发、请求STOP，然后发送成对参数。固件停止底盘并取消手动/GOTO，应用补偿；已有有效OPS帧时同时重新置零，因此原来的地图目标/坐标原点需要重新确认。
3. 用手动原地旋转，在90°、180°等位置停下，查看同页中心X/Y和距零点距离。每次修改参数后重新从零点做同一组试验，可按1mm小步调整，顺逆时针都检查。仅看转满360°的终点不足以判断偏心是否消除。
4. 「保存到电脑」保存当前输入的两项参数为JSON；「加载文件」只填入控件，不自动下发，需再点击应用。「填入初始值」同样不自动下发。填0,0后应用可比较不补偿效果。新版JSON（version=2）中`x_mm`=X左右、`y_mm`=Y前后；旧版`version=1`文件加载时自动迁移一次。

协议：`OPSOFFSET=X,Y`，X=左右安装偏移（左+ / 右−）、Y=前后安装偏移（前+ / 后−），严格两个十进制数，每项范围±500mm，支持负号/小数，不接受指数、NaN、额外字段或尾随字符；物理安装为车左60mm、车后50mm时下发`OPSOFFSET=60.0,-50.0\n`。中断只更新成对请求，任务停车后应用，不在中断中做三角运算。该命令即使手动输入也会取消底盘动作并重新置零；Qt 可通过命令终端手输，其模拟器同样支持，模拟器假设真实安装就是左60/后50，演示残差，不代替实车验证。

调参值只保存在F407 RAM，断电恢复后左60/后50的固件默认值；电脑JSON不等于Flash保存。当前24通道协议不扩展，没有参数ACK/回读，界面明确显示“已请求”，以实车旋转遥测验证。位置遥测现每次发送前刷新，手动控制或静止时也能观察补偿结果。

验证：`python Tests/hardware/test_ops_offset.py`验证真实C函数的旋转、平移、非零航向ZERO、置零后物理正向、原始接口、越界拒绝和中断状态恢复；Qt `python -m unittest -v test_debugger`覆盖应用、文件读写、模拟残差，以及遥测方向与场地轴序一致（`test_telemetry_direction_matches_field_axes`）；统一坐标由`python Tests/hardware/test_coordinate_chain.py`用源码文本断言锁定；固件EIDE编译。没有实车/烧录验证。


## 底盘四轮锁轴：使能 / 失能（2026-09-15）

「底盘调参」顶部新增「使能电机（锁轴）」「失能电机（不锁轴）」，对应固件
`WHEELEN` / `WHEELOFF`，统一作用于 1~4 号 ZDT_X42S 轮电机，不改变 DM 电机和
28/35 步进。`STOP` 只停车并失能 DM，**不改变锁轴状态**。

- 使能（锁轴）：四轮保持位置。固件在 `main.c` 启动时已使能，本按钮用于失能后恢复。
- 失能（不锁轴）：四轮可自由推动，用于手动摆车、推回启停区或机械调试。
  下发前主机先停止键盘续发并请求 STOP，固件侧也会先停车再失能。

**失能后固件不再向四轮下发任何速度帧（2026-09-16 修复）。** ZDT_X42S 在速度模式下
收到任意速度命令都会重新使能并锁轴，而本按钮的 `_manual_stop()` 会先发一条 `STOP`，
`STOP` 与 `WHEELOFF` 落在同一个 20 ms 任务周期里；早先的固件先发失能帧、再由 `STOP`
分支发出速度 0 帧，轮子立刻被重新使能，表现为**"已失能但仍然锁轴"**。修复后固件把
锁轴切换排到每周期最后，且失能后所有停车路径只清软件目标，因此前一条 `STOP` 不再有
影响。**必须烧录 2026-09-16 之后的固件**，只更新上位机无法解决。

**固件在失能期间丢弃 `GOTO`、`MANUAL` 和 `ZDT` 单轮测试**，必须显式 `WHEELEN`
恢复。原因是释放锁轴时位置环仍会持续输出轮速，且手动推车可能被残留命令驱动。
上位机在失能状态下同样拒绝下发地图 GOTO、键盘遥控和手动向量，并在底盘页状态栏
与地图状态栏说明原因。

`WHEELEN`/`WHEELOFF` 走普通命令队列（不是紧急队列），但会先触发本地停车、清理
待发 MANUAL，避免切换后仍周期发送手动命令。

固件无状态回读：界面显示的「已请求」只是本机发出的最后一条命令，上电或复位后
固件默认已使能，界面不会自动同步。在命令终端手输 `WHEELEN`/`WHEELOFF` 也会同步
界面状态。模拟模式支持该状态并拒绝运动命令，但不伪造 UART4 应答。

验证：`python -m unittest -v test_debugger`（离屏 Qt，无硬件）；工程根目录
`python Tests/hardware/test_debug_wheel.py`（需要 GCC，编译真实使能/失能服务函数、
`Debug_ChassisStop` 闸门、解析闸门与驱动接线）。本次未连接设备、未发送实际运动命令，
固件必须重新烧录。
