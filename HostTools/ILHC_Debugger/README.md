# ILHC 调试上位机

配套 `STM32F407VET6_ILHC` 工程 `Hardware/debug_usart.c`（USART1 调试模块）的 PC 端调试软件，
用于替代 VOFA+ 完成麦轮底盘与 DM-J4310 电机的在线调参、波形观察和数据记录。

![协议] USART1 @ 115200 8N1 —— 遥测：`24×float + 0x00 0x00 0x80 0x7F`（100 字节/帧，标准 VOFA+ JustFloat，50 Hz）；
命令：ASCII 每行一条（`\r` / `\n` 结尾，不区分大小写）。

## 功能

| 模块 | 说明 |
|---|---|
| 通道波形 | 24 通道按 4 组（OPS 定位 / 底盘参数 / DM 反馈 / DM 目标）分 subplot 实时显示，时间窗 10~120 s，可暂停/清除，通道经分组下拉菜单勾选（按钮实时显示各组勾选数） |
| 比赛场地地图 | 按初赛场地示意图 1:1 绘制（2400×2400mm：启停区1/2、原料区、暂存区、粗加工区、4 块物料区、二维码板）。**点击地图任意位置，小车即通过 `GOTO=x,y,z` 移动到该点**；实时显示车体位置、航向箭头与行驶轨迹；支持 OPS→场地坐标映射校准（原点 X/Y + 旋转角）；目标航向可选保持当前 / 场地 0°~270° |
| 底盘调参 | KPX/KPY/KPZ/XVMAX/ZVMAX/XVMIN/ZVMIN 滑条 + 输入框 + 单独/一键下发，STOP 急停、ZERO 置零，参数从遥测通道实时回读 |
| DM 电机 | DMID/DMMODE/DMPOS/DMVEL/DMKP/DMKD/DMTOR 下发；DMEN/DMOFF/DMZERO 按钮；实际位置/速度/力矩/温度实时显示；状态码中文提示（失能/使能/过压/欠压/过流/过温/通信丢失/过载） |
| 命令行 | 任意命令手动下发，带时间戳日志、历史记录（↑/↓）、快捷按钮 |
| 数据记录 | 24 通道遥测流保存为 CSV（UTF-8 BOM，Excel/pandas 可直接打开），波形缓冲一键导出 |
| 模拟模式 | 内置固件行为模拟器（命令解析/限幅/回读与 debug_usart.c 一致），无硬件即可演示与验证 |

## 环境与运行

- Windows + Python 3.8+，依赖 `pyserial`、`numpy`、`matplotlib`：

  ```bat
  pip install pyserial numpy matplotlib
  ```

- 双击 `启动上位机.bat`，或：

  ```bat
  python ilhc_debugger.py                 :: 正常启动，手动选串口
  python ilhc_debugger.py --port COM3     :: 启动即连接 COM3
  python ilhc_debugger.py --simulate      :: 启动即进入模拟模式（无需硬件）
  python ilhc_debugger.py --selftest      :: 无 GUI 自检（帧解析/命令解析回环）
  ```

## 硬件连接

USB-TTL 模块与板子 **交叉** 连接：模块 TX → PA10 (USART1_RX)，模块 RX → PA9 (USART1_TX)，共地。
命令下发与波形接收同口复用（固件 DMA 空闲中断收命令，50 Hz DMA 发遥测）。

## 命令速查（与固件一致，超出范围自动限幅）

| 分类 | 命令 | 范围 |
|---|---|---|
| 通用 | `STOP` / `ZERO` | 底盘急停并失能 DM / 停车后将 OPS 当前位置置零 |
| 通用 | `PING` | 调试动作心跳；本上位机连接后每 200ms 自动发送 |
| 底盘 | `GOTO=x,y,z` | OPS 全局定位移动到目标点；z（航向 °）可省略=保持当前；x/y ±3000 mm。**需固件支持（重新编译烧录）** |
| 底盘 | `KPX=` `KPY=` `KPZ=` | 0 ~ 50 |
| 底盘 | `XVMAX=` `ZVMAX=` | 0 ~ 3000 |
| 底盘 | `XVMIN=` `ZVMIN=` | 0 ~ 100 |
| DM | `DMID=` | 1 ~ 1791 (0x6FF) |
| DM | `DMMODE=` | 1=MIT，2=位置速度 |
| DM | `DMPOS=` | ±12.5 rad |
| DM | `DMVEL=` | ±30 rad/s |
| DM | `DMKP=` / `DMKD=` | 0~500 / 0~5 |
| DM | `DMTOR=` | ±10 Nm |
| DM | `DMEN` `DMOFF` `DMZERO` | 使能 / 失能 / 保存零点 |

固件无文本应答，上位机参数值以遥测回读通道（mKpx、dm_cmd_pos 等）为准。

## 场地地图与点击导航

1. **固件准备**：`GOTO` 命令为本工程新增（`Hardware/debug_usart.c`），需在 Keil 中重新编译烧录；
   旧固件会忽略该命令（其他功能不受影响）。
2. **设置起始启停区**：车子物理摆进启停区 → 地图页选“启停区1（右上）”或“启停区2（右下）”
   → 点 **⊙ 置为原点并归零**：区中心自动成为坐标原点（映射原点自动填入），
   同时下发 `ZERO` 让 OPS 位置归零，轨迹清空，车标显示在区中心。
3. **出发**：点击地图任意位置，或用“快速前往”按钮（原料区/暂存区/粗加工区/回启停区），
   小车以当前 XVMAX/ZVMAX 限速移动；点击 **■ 停止** 或发送 `STOP` 随时取消。
   “回启停区”到点后自动朝向场地内侧（启停区1→270°，启停区2→90°）。
4. **朝向校准（可选）**：若 OPS 零点朝向与场地图纸不一致（车标航向箭头方向不对），
   调整映射“旋转°”直至箭头与实际朝向一致。

## 常见问题

- **连不上 / 无数据**：确认 TX/RX 交叉、波特率 115200、串口未被其他软件（VOFA+ 等）占用。
- **波形乱码/错位**：本上位机按标准 JustFloat 帧尾同步；确认通道数为 24，且串口中没有混入文本输出。
- **连接后动作自动停止**：固件带 1s 调试心跳保护，本上位机会自动发送 `PING`；使用其他终端时也需要周期发送。
- **DM 电机 0x0D 通信丢失**：检查 CAN1 线缆、电机供电与 ID（见工程《调试指令手册》）。
- **模拟模式**：数据为仿真值，仅用于界面演示与参数联动验证，不代表真实硬件。


## 底盘手动控制（2026-09-10）

Qt「底盘调参」新增按住运行的手动按钮：前后、横移、原地旋转、前进/后退叠加左右旋转；也可填写三个有符号速度分量后按住组合运动。默认平移60 RPM、旋转30 RPM，每轴范围-300..300 RPM。这些是轮速混合分量，旋转值不是角速度，三轴叠加单轮最多900 RPM，不使用GOTO的XVMAX/ZVMAX。

地址按俯视、车头朝上：左前1、右前2、左后3、右后4。实际转向沿用已有麦轮速度解算；第一次低速核对运动方向，可用「前后反向/左右反向/旋转反向」修正手动按键。这些选项仅作用于本次界面手动控制，不改变GOTO或保存到Flash。

协议：`MANUAL=vx,vy,w`，严格三个整数，范围各-300..300，以换行结束；例如`MANUAL=60,0,30`为前后与旋转分量叠加。主机按住期间约100ms续发，固件350ms未收到有效MANUAL即在下次任务服务停车，PING不续期。无OPS也可手动运行。有效MANUAL取消GOTO，有效GOTO结束手动；STOP/ZERO取消手动。`MANUAL=0,0,0`仅停止底盘；界面松开使用全局STOP，因此也会失能DM并取消28/35待发请求。

松开、切页、窗口失去激活、断开、关闭时结束手动续发并请求STOP；线程或串口故障靠固件独立超时兜底。停车时间受现有任务周期、串口阻塞影响，不是硬实时保证。上位机显示的是发送请求，没有固件手动状态ACK。串口遥测保持24通道不变。

Qt新增按钮；原版上位机可在终端发送该命令，其模拟器同步支持手动运动及超时。真实使用需要烧录新增MANUAL支持的F407固件，OPS固件不因本功能而修改。本次测试不连接设备、不发送实际运动命令。


## OPS 安装偏心补偿（2026-09-10）

F407的`Hardware/ops.c`默认补偿车体后偏50mm、左偏60mm，即`rx=-50mm, ry=+60mm`。rx/ry表示从四驱动轮几何中心指向OPS两条滚动测量直线交点的车体向量；前为+X、左为+Y。与当前OPS模式2按此前约定接轮、yaw逆时针为正配套；实际方向反向时要先确认原始OPS轴和yaw，GUI手动电机反向开关不会改变OPS坐标。

补偿由F407执行一次，不修改OPS板固件。公式：`中心相对位移 = 原始OPS位移 - (R(yaw)-R(参考yaw))*r`。首帧航向是未ZERO时的参考；建议上电保持静止并收到有效OPS数据后ZERO。ZERO保存原始位置和当时yaw，保留工程既有坐标反号：`GetPosition = -(原始相对位移 - 偏心旋转位移)`。yaw不置零。`OPS_GetAbsolutePosition()`和`OPS_GetData()->frame`仍是原始OPS数据；未ZERO的`OPS_GetPosition()`也会补偿。`OPS_ClearZero()`切回首帧参考的补偿坐标。`OPS_SetOrigin(x,y)`的输入仍是原始OPS坐标，调用当时yaw作为该零点的补偿参考。

### 上位机操作

1. 烧录本次F407固件，打开Qt「底盘调参」顶部「OPS安装偏心补偿」。前后=-50、左右=60，单位mm。
2. 点击「应用补偿并置零」。界面停止手动续发、请求STOP，然后发送成对参数。固件停止底盘并取消手动/GOTO，应用补偿；已有有效OPS帧时同时重新置零，因此原来的地图目标/坐标原点需要重新确认。
3. 用手动原地旋转，在90°、180°等位置停下，查看同页中心X/Y和距零点距离。每次修改参数后重新从零点做同一组试验，可按1mm小步调整，顺逆时针都检查。仅看转满360°的终点不足以判断偏心是否消除。
4. 「保存到电脑」保存当前输入的两项参数为JSON；「加载文件」只填入控件，不自动下发，需再点击应用。「填入初始值」同样不自动下发。填0,0后应用可比较不补偿效果。

协议：`OPSOFFSET=-50.0,60.0\n`，严格两个十进制数，每项范围±500mm，支持负号/小数，不接受指数、NaN、额外字段或尾随字符。中断只更新成对请求，任务停车后应用，不在中断中做三角运算。该命令即使手动输入也会取消底盘动作并重新置零；原版上位机可通过命令终端使用。Qt和原版模拟器均支持，模拟器假设真实安装就是后50/左60，演示残差，不代替实车验证。

调参值只保存在F407 RAM，断电恢复后50/左60的固件默认值；电脑JSON不等于Flash保存。当前24通道协议不扩展，没有参数ACK/回读，界面明确显示“已请求”，以实车旋转遥测验证。位置遥测现每次发送前刷新，手动控制或静止时也能观察补偿结果。

验证：`python Tests/hardware/test_ops_offset.py`验证真实C函数的旋转、平移、非零航向ZERO、原始接口、越界拒绝和中断状态恢复；Qt `python -m unittest -v test_debugger`覆盖应用、文件读写和模拟残差；固件EIDE编译。没有实车/烧录验证。
