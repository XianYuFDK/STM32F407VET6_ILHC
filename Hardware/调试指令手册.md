# STM32F407VET6_ILHC 调试指令手册

本文档用于 USART1 调试串口的在线调试，包含底盘、OPS 坐标清零、DM-J4310 电机调试指令及 VOFA+ 数据通道说明。

---

## 1. 调试串口连接

| 项目 | 配置 |
|---|---|
| 调试串口 | USART1 |
| TX | PA9 |
| RX | PA10 |
| 波特率 | 115200 |
| 数据格式 | 8N1 |
| 发送换行 | `\r` 或 `\n` |
| 建议上位机 | VOFA+ / 串口助手 |

VOFA+ 设置：

1. 打开 VOFA+。
2. 选择串口协议为 `JustFloat`。
3. 选择调试串口：`115200 / 8N1`。
4. 开始接收后即可看到第 3 节中的通道数据。

---

## 2. 命令发送规则

- 每行只能发送一条命令。
- 命令名不区分大小写，例如 `DMEN` 和 `dmen` 等价。
- `=` 两侧可以不加空格。
- 参数必须使用浮点数格式，例如 `3.14`、`-2.0`、`0.5`。
- 发送完成后通过回车或换行结束。

## 3. VOFA+ JustFloat 输出通道

当前共 24 个 float 通道：

标准帧格式为 `24×float32 小端 + 00 00 80 7F`，共 100 字节，不包含额外帧头。

坐标约定（对外统一，遥测、`MANUAL`、`GOTO`、`OPSOFFSET`、`KPX`/`KPY` 与 Qt 界面全部按此顺序）：

- `+X` = 小车左方，`-X` = 右方，X 是左右轴
- `+Y` = 小车正前方，`-Y` = 后方，Y 是前后轴
- `+Z` = 逆时针为正，即航向角
- 位置、误差和安装偏移都按物理方向带符号：向左移动 X 增大，向前移动 Y 增大；是否按过 `ZERO` 都不改变符号

移动/定位协议与 OPS 位置遥测的 X/Y 使用 **cm，保留 1 位小数**；固件内部闭环仍使用 mm。
`OPSOFFSET` 是安装标定参数，继续使用 mm；步进电机命令也继续使用机械标定的 mm/0.1mm。

固件内部、串口协议和 Qt 现在完全使用同一轴序、同一符号：`pos_x` 就是 X（左右，+左），
`pos_y` 就是 Y（前后，+前），`mKpx`/`mKpy` 分别控制对应轴；不存在内外交换或取反层。
OPS 原始帧到统一坐标固定为 `X=-raw_y、Y=-raw_x`，没有方向模式或其他分支。
位置、绝对位置、置零、`OPS_SetOrigin()` 和安装偏心补偿共用这组固定映射；
不要单独修改 `rx/ry` 或 `origin_x/origin_y`。Z 仍统一为逆时针为正。

| 通道 | 名称 | 含义 |
|---|---|---|
| 0 | pos_x | OPS 当前 X 坐标（左右轴，+左，cm，1 位小数） |
| 1 | pos_y | OPS 当前 Y 坐标（前后轴，+前，cm，1 位小数） |
| 2 | zangle | OPS 当前航向角（逆时针为正） |
| 3 | devx | X 轴位置误差（左右轴，cm） |
| 4 | devy | Y 轴位置误差（前后轴，cm） |
| 5 | devz | 航向角误差 |
| 6 | mKpx | X 轴 P 系数（左右控制） |
| 7 | mKpy | Y 轴 P 系数（前后控制） |
| 8 | mKpz | 航向 P 系数 |
| 9 | XYVmax | X/Y 最大控制限幅 |
| 10 | ZVmax | 航向最大控制限幅 |
| 11 | SpeedTarget[0] | 1 号轮目标速度 |
| 12 | dm_id | DM 电机 ID |
| 13 | dm_pos | DM 电机实际位置 |
| 14 | dm_vel | DM 电机实际速度 |
| 15 | dm_torque | DM 电机实际力矩 |
| 16 | dm_status | DM 电机状态/故障码 |
| 17 | dm_t_mos | DM 电机 MOS 温度 |
| 18 | dm_t_rotor | DM 电机线圈温度 |
| 19 | dm_cmd_pos | DM 电机目标位置 |
| 20 | dm_cmd_vel | DM 电机目标速度 |
| 21 | dm_kp | DM 电机 MIT Kp |
| 22 | dm_kd | DM 电机 MIT Kd |
| 23 | dm_torque_cmd | DM 电机 MIT 前馈力矩 |

## 4. 通用调试命令

### STOP
```text
STOP
```
停止底盘四个 ZDT_X42S 电机、取消 GOTO，并失能正在调试的 DM 电机。

### ZERO
```text
ZERO
```
以当前 OPS 坐标作为新的本地零点，不清除 OPS 模块数据。

置零后向左 X 增大、向前 Y 增大；当前航向同时设为 Z=0，之后逆时针转动 Z 增大。

注意：`ZERO` 会清零 OPS 的 X/Y/Z，不清零 DM 电机。
执行 ZERO 前固件会先取消 GOTO 并停止底盘，避免置零移动坐标原点后仍在执行的目标被误判。

### GOTO（全局定位移动）
```text
GOTO=120.0,80.0,90.0
GOTO=120.0,80.0
```
- 参数依次为：目标 X（cm，1 位小数，场地左右，+左）、目标 Y（cm，1 位小数，场地前后，+前）、目标航向角（°，逆时针为正）
- 例：`GOTO=120.0,80.0,90.0` 表示场地左方 120.0cm、前方 80.0cm、航向 90°；`GOTO=-120.0,80.0` 表示右方 120.0cm、前方 80.0cm，航向保持当前值
- 第 3 个参数可省略，省略时保持当前航向
- X/Y 对外范围 ±300.0 cm；固件在解析边界换算为整数 mm 后继续使用原有位置环
- 收到后底盘以当前调试限幅速度（XVMAX/ZVMAX）连续移动到目标点，
  每 20ms 执行一步 P 控制（`MecanumControl_GotoOPS`），到位后停止并清除目标
- 再次发送 `GOTO` 可随时更换目标；发送 `STOP` 立即停止并取消目标
- 上位机"比赛场地地图"页点击地图即自动下发此命令

## 5. 底盘调试命令

### 5.1 定位 P 系数

| 命令 | 含义 | 默认值 | 范围 |
|---|---|---|---|
| `KPX=2.3` | 设置左右轴（X 轴）P 系数 | 2.3 | 0.0 ~ 50.0 |
| `KPY=2.3` | 设置前后轴（Y 轴）P 系数 | 2.3 | 0.0 ~ 50.0 |
| `KPZ=9.0` | 设置航向角 P 系数 | 9.0 | 0.0 ~ 50.0 |
| `GOTO=x,y,z` | OPS 全局定位移动到目标点 | — | x/y ±300.0 cm（1 位小数） |
| `PING` | 调试动作运行心跳 | — | 建议每 200ms 发送 |

`KPX` 直接写 X 左右轴增益 `mKpx`，`KPY` 直接写 Y 前后轴增益 `mKpy`。
遥测 ch6/ch7 同步回读这两个变量。

执行 GOTO 或 DM 调试期间，固件超过 1 秒未收到任何命令或 `PING`，会自动停车并失能 DM。

### 5.2 速度限幅

| 命令 | 含义 | 默认值 | 范围 |
|---|---|---|---|
| `XVMAX=1600` | X/Y 最大定位控制量 | 1600 | 0 ~ 3000 |
| `ZVMAX=750` | 航向最大定位控制量 | 750 | 0 ~ 3000 |
| `XVMIN=5` | X/Y 最小补偿量 | 5 | 0 ~ 100 |
| `ZVMIN=5` | 航向最小补偿量 | 5 | 0 ~ 100 |

示例：

```text
KPX=2.0
KPY=2.0
KPZ=8.0
XVMAX=1200
ZVMAX=600
```

### 5.3 底盘/OPS 调试流程

```text
# 1. 观察当前 OPS 坐标
# 2. 设置当前点为零点
ZERO

# 3. 调节定位参数
KPX=2.0
KPY=2.0
KPZ=8.0
XVMAX=1200
ZVMAX=600

# 4. 需要停止底盘时
STOP
```

## 6. DM-J4310-2EC 电机调试命令

调试串口目前默认调试一个 DM 电机，默认电机 ID 为 `1`。

### 6.1 基础命令

| 命令 | 含义 |
|---|---|
| `DMID=1` | 设置 DM 电机 ID，范围 1 ~ 0x6FF |
| `DMEN` | 写入当前控制模式寄存器，使能电机，并开始周期下发控制帧 |
| `DMOFF` | 失能 DM 电机，停止下发控制帧 |
| `DMSTOP` | `DMOFF` 的别名 |
| `DMZERO` | 将 DM 电机当前位置保存为零点 |

### 6.2 控制模式

| 命令 | 含义 |
|---|---|
| `DMMODE=1` | MIT 模式 |
| `DMMODE=2` | 位置速度模式 |

发送 `DMEN` 时，驱动会自动向寄存器 10 写入当前模式。

### 6.3 MIT 模式参数

| 命令 | 含义 | 范围 |
|---|---|---|
| `DMPOS=0.0` | 目标位置，单位 rad | -12.5 ~ 12.5 |
| `DMVEL=2.0` | 目标速度，单位 rad/s | -30.0 ~ 30.0 |
| `DMKP=2.0` | Kp | 0.0 ~ 500.0 |

### 6.4 位置速度模式参数

| 命令 | 含义 | 范围 |
|---|---|---|
| `DMPOS=3.14` | 目标位置，单位 rad | -12.5 ~ 12.5 |

## 9. 注意事项

1. DM 电机默认不会自动使能，必须发送 `DMEN` 才会开始发送控制帧。
2. `DMPOS`、`DMVEL` 等参数会先保存，只有 `DMEN` 后才会持续下发。
3. 调试过程中请不要同时移动底盘和 DM 电机，避免相互影响。
4. 调节 DM 电机时建议先保持 `DMOFF`，确认参数后再使能。
5. `P_MAX / V_MAX / T_MAX` 必须与达妙调试工具中的电机参数一致。
6. 若 DM 电机出现 `0x0D` 通信丢失，请检查 CAN2（PB5/PB6）线缆、电机供电和电机 ID。
7. 急停时发送：
   ```text
   DMOFF
   ```
8. 底盘急停时发送：
   ```text
   STOP
   ```

# 28/35步进调试扩展（2026-09-10）

USART1新增单次请求（CR/LF结束），由任务提交CAN，不在接收中断发送。

| 命令 | 参数 |
| --- | --- |
| `S35MOVE=1000,50` | 高度0.1mm整数、线速度mm/s整数；高度430–2030，速度1–2184 |
| `S28MOVE=2000,50` | 半径0.1mm整数、线速度mm/s整数；半径1200–2860，速度2–65535 |
| `S35RAW=0,1000,100` / `S28RAW=0,1000,100` | 方向0/1、绝对位置计数0–UINT32_MAX、RPM 1–65535 |
| `S35HOME` / `S28HOME` | 执行驱动原有回零命令，不等待回零完成 |
| `S35CANCEL` / `S28CANCEL` | 撤销该电机待发请求，不是停机命令 |

机械换算采用stepper_2835驱动原车标定，协议范围不是机构允许速度。
每台电机保留最新待发请求；邮箱忙最多重试1秒，HAL_ERROR丢弃请求而不重试。
STOP和失联清除待发请求，不能停止已经执行的28/35运动；未推定未验证的停机协议。
原24通道遥测保持不变（位置/误差的 X/Y 现为 cm），没有新增文本ACK或28/35到位反馈，发送不等于执行成功。
Qt地图采用启停区1中心为零、左+X、上+Y；控制台GOTO与原始遥测仍为OPS坐标。2026-09-16 坐标统一后，场地 +X=左、+Y=前 已与第 3 节的协议轴序一致；2026-09-17 起移动/位置单位改为 cm。


## 底盘手动控制（2026-09-10）

Qt「底盘调参」新增按住运行的手动按钮：前后、横移、原地旋转、前进/后退叠加左右旋转；也可填写三个有符号速度分量后按住组合运动。默认平移60 RPM、旋转30 RPM，每轴范围-300..300 RPM。这些是轮速混合分量，旋转值不是角速度，三轴叠加单轮最多900 RPM，不使用GOTO的XVMAX/ZVMAX。

地址按俯视、车头朝上：左前1、右前2、左后3、右后4。实际转向沿用已有麦轮速度解算；第一次低速核对运动方向，可用「左右反向/前后反向/旋转反向」修正手动按键。这些选项仅作用于本次界面手动控制，不改变GOTO或保存到Flash。

协议：`MANUAL=X,Y,W`，X=左右速度、Y=前后速度、W=旋转速度（逆时针为正），严格三个整数，范围各-300..300，以换行结束；例如`MANUAL=0,100,0`为前进、`MANUAL=0,-100,0`为后退、`MANUAL=100,0,0`为左移、`MANUAL=-100,0,0`为右移、`MANUAL=0,0,100`为逆时针自转，`MANUAL=0,60,30`为前进与逆时针旋转分量叠加。固件按`MecanumControl_MoveVelocity(v[0], v[1], v[2])`原序调用，协议、内部和麦轮层完全同号。主机按住期间约50ms续发，固件350ms未收到有效MANUAL即在下次任务服务停车，PING不续期。无OPS也可手动运行。有效MANUAL取消GOTO，有效GOTO结束手动；STOP/ZERO取消手动。`MANUAL=0,0,0`仅停止底盘；界面松开使用全局STOP，因此也会失能DM并取消28/35待发请求。

实车轮序为俯视左前1、右前2、左后3、右后4。固件麦轮矩阵保持 O 型逻辑轮速公式，
`SetMotorVoltageAndDirection()` 只把逻辑轮速正号转 CW、负号转 CCW，不再额外翻转 2/4 号电机。
W 的最终下发图案为 `[+ - + -]`，A 左移为 `[- - + +]`，Q 逆时针为 `[- - - -]`。
若实车方向仍不对，先核对电机地址、物理轮位和驱动器方向位，不要在移动控制层叠加隐藏的反转。

上位机界面后来由按住按钮改为键盘遥控（W前进、S后退、A左移、D右移、Q逆时针、E顺时针、Shift低速、空格停车），发出的命令与上述协议完全一致，只是三个分量的顺序按X(左右)、Y(前后)、W排列。

松开、切页、窗口失去激活、断开、关闭时结束手动续发并请求STOP；线程或串口故障靠固件独立超时兜底。停车时间受现有任务周期、串口阻塞影响，不是硬实时保证。上位机显示的是发送请求，没有固件手动状态ACK。串口遥测保持24通道不变。

Qt新增按钮；原版上位机可在终端发送该命令，其模拟器同步支持手动运动及超时。真实使用需要烧录新增MANUAL支持的F407固件，OPS固件不因本功能而修改。本次测试不连接设备、不发送实际运动命令。


## OPS 安装偏心补偿（2026-09-10）

F407 的 `Hardware/ops.c` 默认补偿 OPS 安装在车体中心左 60mm、后 50mm，即统一坐标
`(X=+60, Y=-50)mm`。`OPS_SetMountOffset(x_mm,y_mm)` 的形参顺序与协议一致：
`x_mm` 是 X 左右偏移（+车左），`y_mm` 是 Y 前后偏移（+车头）。OPS 原始帧实测
`+x_raw=车右、+y_raw=车头`，因此内部换到原始帧的安装分量为
`(-60,-50)mm`，再映射为统一坐标。

补偿由 F407 执行一次，不修改 OPS 板固件。公式仍为
`中心位移 = 原始位移 - (R(yaw)-R(参考yaw))*r`，只是在 `ops.c` 内先把原始
`(x_raw,y_raw)` 映射为 `(X,Y)`。建议上电保持静止并收到有效 OPS 数据后
`ZERO`。置零后向前使 `Y` 增大、向左使 `X` 增大，航向以当前姿态为 `Z=0`。
`chassis_move` 的误差定义为 `目标 - 当前`，必须与 OPS 输出保持同一负反馈方向。
`OPS_GetAbsolutePosition()` 和 `OPS_GetData()->frame` 仍返回原始 OPS 数据；
`OPS_GetPosition()` 返回统一坐标和补偿结果。

### 上位机操作

1. 烧录本次 F407 固件，打开 Qt「底盘调参」顶部「OPS安装偏心补偿」。填写
   `X 左右=60`、`Y 前后=-50`，单位 mm；控件顺序与 `OPSOFFSET` 完全一致。
2. 点击「应用补偿并置零」。界面停止手动续发、请求STOP，然后发送成对参数。固件停止底盘并取消手动/GOTO，应用补偿；已有有效OPS帧时同时重新置零，因此原来的地图目标/坐标原点需要重新确认。
3. 用手动原地旋转，在90°、180°等位置停下，查看同页中心X/Y和距零点距离。每次修改参数后重新从零点做同一组试验，可按1mm小步调整，顺逆时针都检查。仅看转满360°的终点不足以判断偏心是否消除。
4. 「保存到电脑」保存当前输入的两项参数为 JSON；「加载文件」只填入控件，不自动下发，需再点击应用。「填入初始值」同样不自动下发。填 `0,0` 后应用可比较不补偿效果。新版 JSON（version=2）键与统一坐标一致：`x_mm`=X左右偏移、`y_mm`=Y前后偏移；加载旧版 version=1 文件时会自动迁移一次。

协议：`OPSOFFSET=X,Y`，X=左右安装偏移（左+ / 右−）、Y=前后安装偏移（前+ / 后−），严格两个十进制数，每项范围±500mm，支持负号/小数，不接受指数、NaN、额外字段或尾随字符；物理安装为车左60mm、车后50mm时下发`OPSOFFSET=60.0,-50.0\n`。固件内部 `OPS_SetMountOffset(x_mm,y_mm)` 与协议同序同号。中断只更新成对请求，任务停车后应用，不在中断中做三角运算。该命令即使手动输入也会取消底盘动作并重新置零；Qt 可通过命令终端手输，其模拟器同样支持，模拟器假设真实安装就是左60/后50，演示残差，不代替实车验证。

调参值只保存在F407 RAM，断电恢复后50/左60的固件默认值；电脑JSON不等于Flash保存。当前24通道协议不扩展，没有参数ACK/回读，界面明确显示“已请求”，以实车旋转遥测验证。位置遥测现每次发送前刷新，手动控制或静止时也能观察补偿结果。

验证：`python Tests/hardware/test_ops_offset.py`验证真实C函数的旋转、平移、非零航向ZERO、原始接口、越界拒绝和中断状态恢复；Qt `python -m unittest -v test_debugger`覆盖应用、文件读写和模拟残差；固件EIDE编译。没有实车/烧录验证。


## 张大头底盘单电机限时测试（ZDT）

格式：`ZDT=地址,有符号转速,运行秒数`，以换行结束；地址1~4，转速-300~300 RPM，秒数1~5。
正数方向位0，负数方向位1；实际轮子正反转与安装有关。速度单位以驱动器Emm配置为准。

```text
ZDT=3,50,2
ZDT=3,-50,2
ZDT=4,50,2
ZDT=4,-50,2
STOP
```

每条分别发送，等上一次自动停止再测试下一条。先架空底盘，退出上位机手动控制，使用自定义指令发送入口；115200、8N1、文本发送并追加换行。单片机收到后先停止四轮，再重新使能指定电机，等待至少100ms，以加速度参数100运行指定秒数，最后发送FE98专用停止帧。无需OPS，也无需连接其他电机。

这是有界单次测试，不需要周期重发或PING；最长5秒后自动停止。测试期间忽略新的ZDT/MANUAL/GOTO，STOP、ZERO、OPSOFFSET会取消测试。测试结束后新的手动指令可重新驱动车轮，因此不要同时按住手动控制按钮。转速0只停车，不使能。

仍保持24通道JustFloat遥测，不新增ASCII成功回执；上位机TX日志不代表单片机执行成功，也不代表电机应答。固件必须重新烧录，接线为UART4：PA0 TX接驱动器RX，共地；PA1为MCU RX。当前电机驱动没有ACK解析，串口发送失败也无法保证物理停车，调试时保留断电手段。


### ZDT文字应答（新增，以本节为准）

收到以换行结束的ZDT命令后自动暂停JustFloat遥测，改为USART1 DMA发送ASCII应答。发送`VOFA`并追加换行恢复24通道遥测。切换时可能仍有一帧旧遥测在途。

- `ACK ZDT ACCEPTED`：格式及范围合法，单片机已接收并入队。
- `ERR ZDT BUSY`：测试正在执行或有停止等请求待处理，本条未执行。
- `ERR ZDT FORMAT: ZDT=1..4,-300..300,1..5`：格式/参数错误，未执行。
- `ACK ZDT RUN_REQUESTED (NO MOTOR ACK)`：任务已调用指定电机速度驱动接口。
- `ACK ZDT STOP_REQUESTED (NO MOTOR ACK)`：时间到或零速请求，已调用停车接口。
- `ACK ZDT CANCELLED (NO MOTOR ACK)`：STOP/ZERO/安装参数请求取消测试。

这些都是单片机调试应答，不是电机回复。当前底层发送接口不返回HAL状态，因此REQUESTED不保证UART发送成功，更不保证电机执行成功。事件队列可缓存15条应答，满时丢新应答，不影响停止逻辑。上位机文本显示模式查看即可；完成测试后用VOFA恢复波形。无任何应答时先检查新固件、USART1接线及命令换行。


### UART4电机真实回包调试（新增）

新固件在首次电机使能前启动UART4逐字节中断接收。PA0接驱动器RX、PA1接驱动器TX并共地，115200/8N1。仅支持F3/F6/FE四字节应答；驱动器需允许返回应答并使用固定6B校验配置。

发送`ZDT=4,50,2`加换行后，文字模式会显示收到的真实数据，例如：
```text
ZDT RX: 04 F3 02 6B
ZDT RX: 04 F6 02 6B
ZDT RX: 04 FE 02 6B
```
02表示命令正确应答，非机械运动到位。E2、EE或其他原始状态码原样输出，不冒充成功。RX可能与MCU ACK交错，也可能包括测试切换时其他轮子的停车回复；必须查看地址和功能码。

测试开始500ms内未收到目标地址任何有效控制应答时输出`WARN ZDT NO_VALID_REPLY IN 500MS`；仅为本次电机有无回复的检查，不是每条命令的独立超时判定，也不代表电机必然离线。晚到回复继续显示。超时不会延长测试，也不改变停车流程。

仍可用STOP取消，用VOFA恢复波形。UART4错误由任务重启接收，接收队列及文本队列各最多15帧/条，过载丢新数据。正常VOFA模式排空回包不输出文字。当前不支持长查询帧解析，不报告实际速度；电机TX线路必须连接才能看到真实应答。


### USART1启动提示（2026-09-11）

USART1与DMA初始化后、CAN/OPS/电机初始化前，主动DMA发送一次 `USART1 READY | 串口已初始化 | 115200 8N1`（中文UTF-8）。忙或提交失败由默认任务重试。先打开电脑串口再按单片机复位，避免漏掉一次性消息。接收后仍按原设置输出JustFloat，因此文本终端后续二进制显示可能为乱码；启动ASCII标识本身应清晰。

收到提示仅证明PA9→USB转串口RX→电脑链路正常，不代表PA10接收正常，也不代表电机已上电或初始化完毕。验证RX须发送带换行的ZDT命令并观察ACK，或后续另行增加无运动回环命令。


### PB2 LED手动控制

PB2高电平亮，初始化默认熄灭。发送ASCII命令，末尾追加CR/LF或CRLF：

```text
led on
led off
```

不区分大小写。只控制LED，不触发电机；取消任务心跳闪烁和接收自动亮灯，保持最后一次指令状态。接收中断发布请求，默认任务执行，因此亮灭成功可验证电脑TX→PA10→命令解析→默认任务→GPIO链路，不代表电机应答。本指令不新增文字回执，串口遥测模式保持原样。BOOT0保持正常启动状态，并保留原板PB2下拉。

## 2026-09-11：CAN启动失败隔离

`main.c`中`CAN_Start`失败不再进入`Error_Handler`：关闭CAN中断，保留ErrorCode，置HAL_CAN_STATE_ERROR，继续独立串口驱动及RTOS初始化。不自动重试CAN；修复硬件后重新启动。此改动针对CAN_Start失败，未将所有MX外设初始化错误改为可忽略。

`ERR CAN START FAILED; CAN DISABLED; USART1 AVAILABLE`

## 2026-09-15：底盘四轮锁轴（WHEELEN / WHEELOFF）

| 命令 | 作用 |
| --- | --- |
| `WHEELEN` | 四轮统一使能，电机保持位置（锁轴） |
| `WHEELOFF` | 四轮统一失能，轮子可自由推动（不锁轴） |

- 作用于 1~4 号 ZDT_X42S 电机，不影响 DM 电机、28/35 步进和 24 通道遥测。
- `main.c` 启动时已调用 `MecanumControl_Enable()`，上电默认就是使能状态；
  `WHEELEN` 用于失能后恢复，不是必需的启动步骤。
- 大小写不敏感，`=` 与参数均不需要；每行以 CR 或 LF 结束，与既有命令一致。

任务执行顺序：本周期先处理 STOP/ZERO/OPSOFFSET/GOTO/手动，最后才执行锁轴切换
（取消 GOTO 与手动续发 → `MecanumControl_Stop()` 停车 → 发送四个使能或失能帧）。
`MecanumControl_Enable()` 内部有 100ms 等待，使能请求会让本周期任务变长；
`MecanumControl_Disable()` 不等待。锁轴切换排在最后，保证失能帧是该周期 UART4 上的
最后一批帧。

**失能后固件不再向四轮下发任何速度帧。** ZDT_X42S 在速度模式下收到任意速度命令都会
重新使能并锁轴，所以失能后 `STOP`/`ZERO`/`OPSOFFSET`/主机失联停车只清理软件目标
（`MecanumControl_ClearTarget()`），不再发速度 0 帧。此前的实现在同一周期内先发失能帧，
之后 `STOP` 分支又调用 `MecanumControl_Stop()` 发出速度 0 帧；而 Qt 上位机点击
「失能电机」时会先发 `STOP` 再发 `WHEELOFF`，两条命令落在同一个 20ms 周期里，轮子被
重新使能，表现为**"已失能但仍然锁轴"**。修复后 `MecanumControl_Stop()` 拆分为
"清目标 + 下发速度 0 帧"，任务体的所有停车路径统一走带闸门的 `Debug_ChassisStop()`：
使能状态下发速度帧，失能状态只清目标。

**失能期间 `GOTO=`、`MANUAL=` 被直接丢弃**（与格式错误一样不产生应答），
`ZDT=` 返回 `ERR WHEEL DISABLED; WHEELEN FIRST`。必须显式发送 `WHEELEN` 才能恢复
运动。这样设计是为了避免释放状态下位置环持续输出轮速，也避免手动推车时被残留
命令驱动。`STOP` 只停车并失能 DM，**不改变锁轴状态**；主机失联停车同样不会重新
使能四轮。

`ZDT=` 测试进行中收到 `WHEELEN`/`WHEELOFF` 时，按既有 STOP/ZERO/OPSOFFSET 规则
取消测试并回复 `ACK ZDT CANCELLED (NO MOTOR ACK)`，防止测试阶段1的重新使能把
已失能的轮子重新上电。

无状态回读：没有锁轴确认应答，上位机显示的只是"已请求"。判断实际是否锁轴可以手动
推动轮子确认，或看 `ZDT=` 是否被拒绝。电机本身可以用 `01 3A 6B` 读取状态标志
（`Ens_TF` 位，0/1 分别表示未使能/已使能），但固件目前没有对应的查询命令，需要用
串口助手直接对 UART4 发送。Qt「底盘调参」页新增对应两个按钮，并在失能状态下本地拒绝
地图 GOTO 与键盘遥控；命令终端手输同样同步界面状态。
必须烧录本次固件，旧固件会忽略这两条命令；2026-09-16 的失能时序修复也必须烧录，
否则仍会出现"失能了还是锁"。
